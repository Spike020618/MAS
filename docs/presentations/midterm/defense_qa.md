# 中期答辩评审问答库

使用原则：先用一句话正面回答，再给数字或设计证据，最后主动说明边界。不要把尚未完成的影视离线评测说成已经完成，也不要把 Static AEIC 说成全局最优 Stackelberg 均衡。

## 一、创新点与相关工作

### 1. 你的创新点到底是什么？

本文提出 AEIC-MD：把 AEIC 报告空间、生成前公开合同、Agent 行动选择、真实资源路径和执行后结算组成一个可运行的 Leader–Follower 协议。创新不只是四字段 Prompt，而是让过程行为能够被承诺、选择、执行、记录和实验检验。

### 2. AEIC 不就是结构化 Prompt 吗？

如果只要求输出 A/E/I/C，它确实只是结构化 Prompt。本文额外做了三件事：规则在生成前公开；Agent 先从 Low、AEIC、Verify、Imitate 中选行动；该行动真实改变 Prompt、Token 和验证路径。因此 AEIC 在本文中还是一个可缔约的报告空间。

### 3. 和 Chain-of-Thought、ReAct 有什么区别？

CoT 和 ReAct 主要组织单个模型的推理或工具调用。本文关注多个 Agent 在公开合同下是否选择可检查的资源路径，以及这种选择怎样影响群体决策。AEIC 的作用是跨 Agent 统一报告接口和结算信号，不声称替代 CoT 或 ReAct。

### 4. 和多智能体 Debate 有什么区别？

Debate 主要改变 Agent 之间的信息交换过程；AEIC-MD 研究的是通信发生前，Agent 是否愿意生产独立、完整或经过验证的信息。拓扑控制“信息流向哪里”，本文机制控制“什么信息值得被生产”。

### 5. 和多数投票或 Self-consistency 有什么区别？

多数投票只聚合最终答案，无法区分独立验证和复制性一致。本文在投票之前记录行动、报告、资源使用和证据，因此可以研究共识是怎样形成的。

### 6. 和结果奖励或事后打分有什么区别？

事后评分不能证明生成策略看到了规则。本文要求合同先公开，再由 Agent 选择行动。Outcome-only 对照也表明，仅加入奖励语言并未改善准确率，主结果不能简单归因于“告诉模型有奖励”。

### 7. 和拓扑优化、路由方法相比有什么创新？

拓扑和路由是信息结构与系统调度层；本文把它们视为可控环境或未来设计变量。核心创新是生产激励：行动怎样在公开规则下被选择，并对应真实资源路径。

### 8. 为什么只说一个创新点？

毕业设计采用“一个方法创新点 + 一个系统实现”的结构。AEIC、公开合同、行动空间、信誉更新和验证不是互不相关的多个创新，而是 AEIC-MD 这一统一机制的组成部分。影视系统用于验证该机制的工程可实现性。

## 二、理论与机制设计

### 9. 为什么称为博弈驱动？

因为存在明确的先后顺序：Leader 先承诺信用规则、成本、信息策略和验证预算；Follower 观察合同后选择行动；系统再执行对应路径并结算。实验检验的是公开合同改变后行动分布是否变化。

### 10. 你证明了 Stackelberg 均衡吗？

没有。当前正式实验验证的是固定 Static AEIC 合同下的 follower response，不是动态 Stackelberg 最优性或一般均衡。论文主动把全局最优合同和闭式均衡列为未来工作。

### 11. LLM 没有真实金钱偏好，为什么能谈效用？

这里的效用是协议中的可见信用减行动成本，是诱导模型策略选择的控制变量，不是对模型具有类似人类经济偏好的心理主张。我们只讨论可观察的行为响应。

### 12. Agent 会不会只是遵循 Prompt，而不是在“博弈”？

模型当然通过 Prompt 接收合同；关键不在拟人化动机，而在同一个黑盒策略对不同公开规则是否产生系统性行动变化。奖励—成本扫描提供了方向性响应证据，但我们不把它解释成人类式理性。

### 13. 为什么选择 Low、AEIC、Verify、Imitate 四种行动？

它们覆盖四类具有不同信息价值和资源成本的生产路径：短回答、完整结构化报告、追加验证和利用同伴信息。这样可以区分独立生产、额外核查和低成本跟随。

### 14. 信誉状态有什么必要性？

信誉把多轮历史贡献压缩为后续可用状态，并记录信用与成本的累积影响。当前主实验的核心结论不依赖声称信誉模型已经最优；它是完整协议和系统审计的一部分。

### 15. AEIC 完整是否代表答案正确？

不代表。AEIC 只提供可解析的过程表面；结构完整但事实错误完全可能。因此论文同时使用任务真值、验证路径和最终准确率，且明确不把格式完整等同于真实性。

## 三、实验设计与因果识别

### 16. 主实验比较了什么？

同一批 450 道题分别在 No Mechanism、Outcome Only 和 Static AEIC 下运行。问题、Seed、Agent 数、轮数和聚合方式配对保持一致，主要改变可见合同。

### 17. 为什么需要 Outcome Only？

它用于区分“过程规则有效”与“任何奖励语言都有效”。Outcome Only 的准确率为 67.33%，相对 No Mechanism 没有显著改善，支持过程可观测性而非一般奖励措辞是关键因素。

### 18. 什么是高资源行动率？

它是 AEIC 或 Verify 行动占全部 Agent-Round 的比例：`H(a)=1[a∈{AEIC,Verify}]`。它测量可观察的执行路径，不是心理努力程度。

### 19. 为什么主结果提升这么大？

Static AEIC 不只改变文本格式，而是联合改变行动选择、报告长度、验证和计算资源。主结果是完整机制的联合效应，因此不能归因于某一个字段，也不能说是零成本提升。

### 20. 会不会只是因为用了更多 Token 或更强模型？

额外资源是机制执行的一部分，所以论文同时报告 Token、调用和延迟，不把结果描述为同成本算法优势。研究问题是公开规则能否诱导资源路径并改善结果；严格等算力比较是另一项研究问题。

### 21. 主实验为什么使用分层后端？

行动对应真实资源层级：Low、AEIC 和 Verify 使用不同能力与预算的路径。这样才能验证行动选择具有执行含义。但代价是效果属于整个合同—资源系统，不是纯文本格式的孤立效应。

### 22. 三个数据集分别验证什么？

StrategyQA 覆盖布尔常识推理，MMLU-Hard 覆盖困难知识选择，TruthfulQA 覆盖诱导性前提和常见错误信念。它们用于观察同一机制在不同错误结构中的异质性。

### 23. 为什么 StrategyQA 只提升 4 个点？

其 No Mechanism 基线已达 73.33%，高资源行动增幅也是三域最低。布尔常识任务中额外报告和验证的边际价值可能更有限。但这是与任务结构一致的解释，不是已经完成的因果分解。

### 24. 为什么 MMLU-Hard 提升 20 个点？

它同时出现最大的高资源行动响应（+73.69pp）。困难知识题需要事实提取、选项比较和排除干扰项，完整报告与验证资源可能更有价值。相对错误减少约 69.8%，但仍应避免把任务属性直接写成已证明原因。

### 25. 为什么 TruthfulQA 提升明显？

TruthfulQA 基线最低，问题常包含诱导性前提。显式写出假设、证据和反证有助于暴露“听起来合理”的错误。相对错误减少约 45.9%，但同样属于机制一致性解释。

### 26. 你检验了数据集之间的差异是否显著吗？

没有预注册数据集×处理的交互检验。因此论文报告分域异质性，但不宣称三种任务属性之间存在已证明的因果差异。

### 27. 如何排除随机 Seed 的影响？

两个额外 Seed 复现了主方向：Static AEIC 相对无机制提高 14.67pp，Holm 校正 p=2.40×10⁻⁹。它降低了单次采样偶然性的担忧，但仍不能覆盖所有模型和提示设置。

### 28. Agent 数变化后是否稳定？

3、4、5 个 Agent 条件下准确率位于 87.33%–88.67%。这说明当前范围内没有明显依赖固定 Panel 规模，但不能外推到任意大规模群体。

### 29. 为什么消融没有证明每个字段都必要？

去除一个字段会改变模型对整个合同的理解，不是干净的模块删除。当前各变体准确率仍较高，因此消融只能限定实现边界，不能声称 A、E、I、C 四个字段逐项具有独立因果必要性。

### 30. 信息环境实验说明了什么？

在新增证据、仅社会立场、复制压力和反证条件下，Static AEIC 都提高高资源行动率，并在该组实验中提高准确率。它说明接口在不同同伴信息条件下仍可操作，不证明所有信息干预普遍有效。

## 四、统计与结果可信度

### 31. 为什么使用 McNemar 检验？

最终结果是同一道题在两个条件下的正确/错误配对变量。Exact McNemar 直接检验“由错变对”和“由对变错”的不对称性，适合该设计。

### 32. 为什么进行 Holm 校正？

正式实验包含预设比较族。Holm 校正控制多重比较带来的第一类错误膨胀，同时比最保守的 Bonferroni 更有检验力。

### 33. 样本量够吗？

主实验每域 150 题、共 450 个配对问题，主效应 p=1.23×10⁻¹¹，足以支持 pooled 主结论。分域原因解释和交互效应的功效则有限，所以没有做过强结论。

### 34. 5,850 个样本是怎么来的？

它是八组冻结实验套件中的问题级记录总数，不等于 5,850 道互不相关的新题。答辩时必须同时说明记录单位、条件重复和配对结构，避免夸大样本独立性。

### 35. 有没有选择性报告？

主实验、负结果、消融和 held-out GLM 都保留在主叙事中；特别是 GLM 未复现结果没有隐藏。结果由冻结文件统一复算，旧拓扑实验不作为当前主因果证据。

### 36. 为什么 GLM 没有复现？

同一合同文字对不同模型未必具有相同语义和策略作用。GLM 条件下高资源行动率只变化 0.35pp，准确率差值为 -1.33pp且不显著。这说明合同需要针对后端校准，也是论文的重要边界结果。

### 37. GLM 失败是否否定方法？

它否定的是“同一合同可以无条件跨模型迁移”的强主张，不否定在主后端上观察到的配对效应。正确结论是机制有效性具有模型依赖，而不是普适激励语言。

## 五、系统实现

### 38. 为什么选择影视推荐作为系统？

影视场景同时包含真实候选检索、硬约束、偏好冲突、多样性和理由证据，适合展示行动、验证和共识审计。它是应用验证载体，不进入通用理论定义。

### 39. 系统如何体现论文机制？

请求先生成计划和公开合同，Preference、Diversity、Critic 等角色选择并执行资源路径，输出 AEIC 报告；共识控制器保留证据、异议、Token、延迟和最终排序。

### 40. 系统是不是只有静态页面？

不是。当前后端使用 18,430 部 MovieLens 电影目录，能够运行真实检索、多 Agent 报告、候选共识和完整 Trace。PPT 截图来自同一真实 request id，并保存了 168KB 的运行记录。

### 41. 推荐质量是否已经完成严格评测？

尚未。当前已经证明系统主链路可运行并能产生可审计结果；Hit@K、Recall@K、NDCG@K、约束满足率、证据支持率和延迟统计属于下一阶段收尾，不能在中期汇报中虚构数字。

### 42. 为什么三个推荐的总分相同？

该案例中三部候选获得相同的聚合总分，但目录证据和影片属性不同。它暴露了当前共识评分区分度仍需校准，因此系统同时展示检索、决策和证据分项，而不把总分包装成精确偏好概率。

### 43. 系统怎样避免幻觉影片？

候选必须先来自 MovieLens 正式目录，生成式 Agent 只评审真实候选；硬约束验证保持确定性。推荐理由仍可能出现解释偏差，所以需要通过目录证据引用和 Trace 审计，而不是仅相信自然语言理由。

### 44. API 失败怎么办？

DeepSeek 超时、空 JSON 或结构错误会记录 `agent_degraded`，系统使用确定性 Agent 继续返回安全结果。降级被显式记录，不隐藏为正常共识。

### 45. 为什么只用一个 API 却说多 Agent？

多 Agent 指独立角色状态、提示、行动和报告流程，不要求每个角色来自不同供应商。当前 Preference、Diversity、Critic 复用同一模型端点，以控制后端差异；它们仍有独立角色目标和 Trace。

### 46. 为什么称为去中心化？是否已经完成真实分布式部署？

本文的去中心化是决策与语义报告层面的模拟去中心化：每个 Agent 基于局部状态独立选择行动、生成 AEIC 报告，并按照受控信息策略与其他 Agent 交互；不存在一个中央 Judge 替所有 Agent 生成语义结论。当前实验仍由统一程序承担时钟同步、合同执行、结果聚合和日志复现，因此不声称已经完成跨节点、无中心基础设施的 P2P 部署。论文与汇报统一使用“逻辑去中心化”或“模拟去中心化”说明当前实现边界。

## 六、局限、未来工作与毕业完成度

### 47. 当前最大的局限是什么？

合同语义具有后端依赖；高资源行动与更高计算成本绑定；AEIC 完整不保证事实正确；分域异质性尚未完成交互检验；影视系统离线推荐评测仍待完成。

### 48. 下一步最重要的研究问题是什么？

在不访问测试真值的前提下，如何针对不同后端校准合同，并在准确率、验证成本和延迟之间选择可部署的规则。

### 49. 为什么不继续做更复杂的动态 Stackelberg？

中期阶段优先完成可以防守的固定合同实验和系统闭环。动态最优若没有新的正式验证，会扩大理论承诺而削弱可信度，因此作为未来工作更合适。

### 50. 毕业设计现在完成到什么程度？

方法、主实验、扩展实验、统计分析、英文论文和影视系统主链路已经完成。剩余工作是影视离线评测、中文毕业论文整合和答辩材料固化，属于交付收口而不是重新寻找研究方向。

### 51. 如果只能用一句话总结贡献？

本文把多智能体研究从“怎样聚合答案”前移到“怎样通过生成前公开、可执行的过程合同改变 Agent 的资源行动，并用配对实验检验其对集体决策的影响”。

### 52. 什么结果会推翻你的核心结论？

如果在主后端的配对设计中 Static AEIC 不改变行动分布，或者行动变化没有带来超过 Outcome Only 的决策改善，核心结论就不成立。held-out GLM 的失败已经表明结论不能无条件跨后端推广。

## 七、现场答题模板

遇到未准备的问题时采用三句话：

1. **先给结论：**“当前数据支持的是……，不支持的是……”
2. **给证据：**说明对应实验、样本单位、关键数字或系统 Trace。
3. **给边界：**说明尚未检验的因素，并指出会如何补做，而不是临场编造结果。
