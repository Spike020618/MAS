# 原生 ReDial 训练侧检索增强

本轮对检索底座取得可复算提升。它是训练侧证据和候选质量提升，不是多智能体或博弈机制的独立贡献。没有打开公开 test，也没有打开旧自定义 reserved 数据，没有外部模型调用或费用。

## 结果

全公开验证集：2,286个前缀，3,010个原生推荐目标。

| 方法 | Recall@10 | NDCG@10 | 候选Recall@100 |
|---|---:|---:|---:|
| 原TF-IDF训练邻居50 | 13.79% | 0.08057 | 36.78% |
| 原生实体条件关联 | 16.35% | 见搜索结果 | 48.57% |
| 邻居＋较强实体关联 | 19.34% | 见搜索结果 | 48.74% |
| 邻居＋实体关联＋近期提及 | 21.69% | 0.12263 | 49.83% |

相同旧32例，最终融合 Recall@10 从8/40到12/40；候选覆盖从16/40到24/40。新的64个验证前缀与旧32既不重复前缀ID，也没有原始对话重叠，共83个目标：旧邻居命中14/83，新融合17/83；候选覆盖从32/83到42/83。

全验证集按883个原始对话聚类，10,000次固定种子重抽样，Recall@10增量7.907个百分点，探索性95%区间[6.754,9.079]个百分点。NDCG@10增量0.04206，区间[0.03464,0.04990]。这是重复开发数据上的探索区间，未校正多重搜索，不是独立确认性显著性结论。

## 模型与公式

所有计数和向量器只用 train。所有特征都来自预测时已经发生的对话前缀，目标推荐者当前响应及其实体绝不入输入。

令训练前缀为r，原生目标多重集为T_r。构造目标权重 `Y_rj = count(j in T_r)/len(T_r)`。

1. 文本邻居：训练前缀使用一至二元TF-IDF，min_df=2，最多60,000特征，sublinear_tf；取余弦相似度前50个训练前缀，以相似度乘Y累加候选分数。
2. 实体关联：`C_ej=sum_r 1[e in prefix_entities_r] * Y_rj`，`N_e=sum_r 1[e in prefix_entities_r]`，`P_j`为训练目标出现次数。当前查询实体集合Q上的分数为 `S_entity(j)=sum_e_in_Q C_ej/(max(N_e,1)*max(P_j,1)^0.25)`。
3. 近期提及：只取已发生前缀中的原生影片提及，按逆序 `S_recent(j)=sum_age 0.8^age * 1[mention_age=j]`。提及不当作喜欢，只作为下一推荐影片的预测特征。作者协议未排除已提及影片，本轮也不改该规则。
4. 最终融合：每个组件按当前查询最大分数归一化，`S = norm(S_neighbor) + 0.5*norm(S_entity) + norm(S_recent)`。同分按训练热门顺序，全部6924个原生影片可排序，不插入真实目标。

实体关联不等同于完整KG语义推理；它利用作者已链接的原生实体和训练条件计数。近期提及没有单独构成全部提升：不加入它的实体/邻居融合仍达到19.34%。

## 选择过程与复算

第一轮在全valid探索28个固定组件/融合配置，保留全部结果：`experiments/results/native_retrieval_optimization_v1/search_results.json`。当时的全valid最优是上述三项融合。

随后采用更干净的训练内选择：按原始训练对话ID固定哈希留出1/5，所有同对话前缀只在一边；在这一 train 内验证集上选择完全相同的28组配置。仅凭内验证也选出上述相同三项融合。配置承诺保存后，再fit完整train并评估公开valid，得到相同21.69%。

主用产物：`experiments/results/native_retrieval_inner_v1/`。其中：

- `protocol.json`、`inner_search_results.json`：训练内划分及完整选参轨迹。
- `selected_config.json`：只按训练内留出选出的配置。
- `summary.json`、`comparison_to_original.json`：全部验证、旧32、新64成绩及配对区间。
- `valid.predictions.json`：全valid原生top100与分数。
- `old32.inputs.json`、`new64.inputs.json`：无当前目标字段的模型输入，含原生候选、分数和各组件分数。
- 对应 `.labels.json`：评价标签分离保存。
- 对应 `.evidence.json`：仅来自训练对话的相似实例、其真实下一轮影片、当前前缀实体到候选的训练关联计数；都标记 OTHER 用户和无当前用户事实权限。

新64是按输入ID哈希、排除旧32预先选择；不是依据命中、覆盖或答案难度筛选。当前项目此前已在全valid做探索，因此新64也不能称全局从未见标签的确认集。后续模型对照能检验输入迁移，不能借此洗掉开发历史。

## 接口与检查

入口：`experiments/paired_deliberation/native_retrieval_optimization.py`；训练内选择：`native_retrieval_inner_selection.py`。

```python
train, valid, entities, items = load_train_valid()
model = NativeRetriever(items, entities).fit(train)
config = {"neighbors50": 1.0, "entity_a1.0_b0.25": 0.5, "recent_mentions": 1.0}
candidates = model.rank(enhanced_prefix_row, config, topk=100)
evidence = model.evidence(enhanced_prefix_row, [m["movie_id"] for m in candidates])
```

增强前缀行使用 `id,text,context_movies,context_entities,last_seeker_text`。不要把 `targets` 放进运行时模型材料。已生成输入文件不含该字段。

实际全valid的id、文本和目标序列与原生预处理逐项一致；train与valid原始对话严格不重叠；全部候选属于原生6924集合；新旧模型样本没有原始对话重叠。审计见 optimization_v1/data_audit.json。

新增针对测试覆盖未来电影/实体不可进入前缀、服务证据不依赖当前目标、历史同对话排除、未知实体安全处理；连同原生构建检查共5项通过。未改主runner与ACTIVE计划，也未替代其他Agent的实体映射或候选挑战模块。
