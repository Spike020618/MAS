# 核查诊断：盲选与拟合参数冻结

已完成的下一批入口是 `experiments/paired_deliberation/native_review_diagnostic_data.py`，结果位于 `experiments/results/native_review_diagnostic_v1/`。它没有调用模型，也没有读取原始对话或诊断目标标签；当前产物是候选对清单，并非完整模型请求包。

原训练侧外层诊断已经按原对话划分为核查拟合部分与核查诊断部分。新清单只使用后者的570个前缀、216个对话：先按固定SHA256顺序选对话，再在对话内按另一个固定SHA256顺序选一个前缀，最后根据预测均值差与三个模型成员的差值标准差，选择第4—10名中的一个保留项及第11名以后的一个挑战项。64个任务来自64个不同对话，不按真实胜负平衡，也不读取真实胜负。每个候选池均重新核对为训练侧Sparse前100与KBRD前100的盲并集；不追加正确答案。

`frozen_fit_rates.json` 固定了已经完成的三模型拟合侧条件修正率与保留率，并记录其原始 `summary.json` 的SHA256。它们来自24/24/16平衡抽样，不能解释为自然样本中的无条件准确率，更不能解释为语义真实性认证。GLM/Qwen Flash/Qwen Plus在24个挑战项确实更好的拟合案例中分别修正3/6/9个，是下一阶段的参数假设；其部署效果需要诊断验证。

当前尚未生成对话证据与完整请求。原因是现有 `NativeEvidence.__init__` 会载入完整的 `valid_data.json` 容器；其后 `visible_prefix` 虽然会在当前前缀停止、没有证明未来标签进入预测，但本批要求更严格的“准备阶段不读取诊断movies”，因此不能直接复用这个载入路径并声称满足该要求。应先建立只持有可见前缀的证据装载入口，再追加同权限证据与请求。这个边界不应被误报为已经发现了历史结果的目标泄漏。

下一步生成完整请求并封存后，才允许另行提取64个任务的下一轮推荐目标作评分。当前清单和条件参数不得根据该评分改选；若发现接口错误，另建版本并保留旧产物。

复算命令：

```bash
.venv-native-benchmark/bin/python -m experiments.paired_deliberation.native_review_diagnostic_data
.venv-native-benchmark/bin/python -m unittest experiments.tests.test_native_review_diagnostic_data -q
```

三项测试通过，覆盖确定性、原对话不重叠、目标位置限制、缺失查询与非有限预测拒绝。准备命令的产物使用不可变写入；已有相同目录时应验证旧产物或使用新 `--output`，不要覆盖历史清单。

## 更新：完整实际请求包已生成

`native_review_diagnostic_packets.py` 已生成 `experiments/results/native_review_diagnostic_packets_v1/`：`pair64.inputs.json`、`pair_states.json`、`frozen_fit_rates.json` 及 plan。现在这个新目录的 `complete_request_packets=true`；原纯盲选目录不覆盖，原先false仍保留历史事实。当前64包可直接交实际采集运行器，不需要再等离线“效果验证”。

实现建立仅含fold80训练和公共catalog/KG的安全数据目录，`valid_data.json`固定为空列表。当前请求仅取已封存 `hold20.inputs.json` 中的可见前缀文本，不读取原始hold20对话、未来响应movies或标签。角色文本分段经过逐字往返检查；角色电影ID仅根据训练确定的引用链接还原，未解析引用保留。可见前缀已有的context_movies以“角色未指明的上下文提及”单独提供，不捏造用户角色或喜好。这个差异相对拟合包明确记录在plan；所有评审者收到相同材料，拟合条件率作为待检验假设，不能当已认证诊断效用。

4项针对性测试通过（前缀往返/未知引用、无角色文本拒绝、安全目录不链接valid、非空valid拒绝）；64个实际请求均通过既有 `native_reviewer_calibration.request` schema构造检查。包生成和检查本身未调用API，实际调用由新live runner完成，必须全部封存后另行提取标签评分。
