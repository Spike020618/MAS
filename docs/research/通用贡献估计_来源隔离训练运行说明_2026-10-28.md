# 通用贡献估计：来源隔离与跨任务训练

新入口 `experiments/fit_transfer_contribution.py`，不修改旧E2拟合协议。没有API调用；也没有代跑用户采集或拟合。

## 为什么另设协议

原题分组不能阻止同一篇资料跨训练/诊断。本入口将同原题/对话、或使用相同规范化全文的任务连接成组件，整个组件只进入一个集合。来源URL不同但全文相同仍连接；不同节选/近义文本目前不自动识别为相同来源，这是保守精确内容去重边界，不是语义独立证明。

特征仅使用行动前的来源长度、已见来源数、状态版本、候选数和是否弃答。没有题目ID、来源ID、URL、标题文本、正文文本或任务类型身份特征。来源长度本身仍可能形成相关性，不保证不存在所有内容相关性。

## 命令

在项目根目录运行。先固定不读取标签的分组：

```bash
.venv-native-benchmark/bin/python -m experiments.fit_transfer_contribution \
  --run-root experiments/results/e2_action_acquisition_160_live_v1 \
  --output experiments/results/transfer_source_heldout_v1 --prepare-only
```

同一源库连接成巨大组件时，这条命令可能拒绝分割，这是应披露的数据限制。应获取独立来源/任务，而不是换seed拆开组件。当前QA共享59文档的库很可能有这个问题。

采集全部封存后，用同一输出拟合：

```bash
.venv-native-benchmark/bin/python -m experiments.fit_transfer_contribution \
  --run-root experiments/results/e2_action_acquisition_160_live_v1 \
  --output experiments/results/transfer_source_heldout_v1 --fit
```

跨任务直接迁移例子（QA只进入诊断；其余组件分训练/校准）：

```bash
.venv-native-benchmark/bin/python -m experiments.fit_transfer_contribution \
  --run-root experiments/results/e2_action_acquisition_160_live_v1 \
  --output experiments/results/transfer_leave_qa_v1 --held-kind qa --prepare-only
```

完成后同命令改为`--fit`。反向用`--held-kind rec`和新输出目录。若来源连接QA与推荐会拒绝跨任务隔离声明，不静默剔除或混入。

## 产物与边界

`split_commitment.json`固定任务/来源组件与60/20/20切分；`observations.json`保留失败和不合格baseline；`model.joblib`包含收益/误改模型、校准偏移与split SHA；`diagnostic_predictions.json`与`summary.json`是组外开发诊断。

模型可用joblib加载，`gain.predict([features(task,case)])+gain_bias`预测动作收益，`damage.predict`为未做概率校准的误改评分，不能称概率。与现有E2ActionCalibrator模型schema不同，不能将该文件传给旧加载器冒充兼容。当前是训练/诊断入口，接入最终分配器须增加显式适配，不宣称已接入。

这是对训练侧随机来源动作的预测，不是通用机制有效性证明或因果VOI。未来固定机制跨环境/来源/模型评价仍需真实实验。3项测试验证组件传递、巨大组件拒绝、特征身份隔离。
