# 来源贡献博弈：实现与开发验证

状态：工程闭环与开发验证，不是独立测试验收。正式目标仍为有限合同、明确收益模型下的Stackelberg–Nash解及实际执行验证。

后续更新：本稿记录的开发阶段已结束；锁定合同的新题在线验收已经完成，见[在线验收报告](locked_stackelberg_acceptance_2026-10-19.md)。执行检查通过，但独立质量收益未复现；以下开发阶段结果不替代后续评测。

## 1. 已实现

- `experiments/core/mechanism/source_sharing.py`：固定来源权重支付、Follower效用、势函数、单方后悔、全部纯Nash枚举、逐Agent异步严格收益改进。
- `AcquisitionLedger`：对真实来源字节复算SHA256，按Agent权限读取并签发内部获取记录；重复读取不增加贡献；实际凭据集合必须匹配最终承诺动作。
- 独立旧求解器交叉核对新模块的均衡集合。中央枚举器不参与实际局部更新。
- 真实API开发采集：任务键、Prompt哈希、不可变协议、文件锁、成功响应逐条fsync、断点跳过、失败日志、格式与截断检测、请求/返回模型标识、Token与耗时。

内部账本不是远程抗攻击凭证服务；当前没有真实资源奖励账户。理论动作费用采用D=0、R=0.75的诊断单位，不冒充实测API价格。

## 2. 无API执行检查

来源使用此前12题的真实Wikipedia快照，逐一核对文件哈希与摘录哈希。每题5档预算，每档覆盖8种初始行动及6种轮转次序，共2,880次规范策略运行。

全部通过：终点无可获利单方偏离；结算不超预算；实际获取记录匹配承诺。来源授权与完整性、重复来源去重、势差及同步振荡反例另有测试。

这2,880次不是2,880道题，也不是模型调用，更不能作为统计独立样本。

结果：`experiments/results/mechanism/stackelberg/source_sharing_runtime_v2/integration_audit.json`。

## 3. 首轮真实报告采集及失败

6道此前已接触的开发题，3 Agent，D/R各2次，共72次API响应。全部完成，消耗46,466 Token；请求耗时合计102.27秒，不等于包含开发、等待、历史建库的总墙钟时间。

9份字段类型不符合预期，37份有效报告选择弃答，无截断。原提示强调缺乏来源时不得声称验证，却未明确允许使用自身知识，也未明确AEIC各字段类型，形成接口混杂。该轮所有预算的悲观均衡质量估计均为25%，不能据此论证激励改善效果。

原始结果完整保留，不删除失败样本、不隐性重跑。v2结果目录：`experiments/results/mechanism/stackelberg/source_sharing_pilot_v2/`。

## 4. 通用接口修复

新版本统一允许自身知识与补充来源，来源缺失不自动要求弃答；明确A/E/I均为字符串。不改问题、不改来源、不加专用检查器，不按答案修改某类题目的提示。

这是开发阶段环境修复，不是同一冻结环境下的合同对比；v2/v3必须分开。两版均使用已曝光题，不能作为最终未见测试。新目录：`experiments/results/mechanism/stackelberg/source_sharing_pilot_v3/`。

## 5. 模型版本

本轮请求别名为`deepseek-chat`，服务返回模型字段为`deepseek-flash`。返回字段不是不可变权重证明，但必须披露。不可未经核验与历史DeepSeek实验合并成同模型结果；后续同时记录请求别名、返回标识、日期与可用指纹。

## 6. Leader开发求解的范围

开发分析枚举所有联合行动对应的潜在报告，并比较5档预算：0、0.5、1、2、4。每题固定来源包，开发集使用统一预算；不逐题看真值选择预算。

对资源与支付权重的9种组合完整列出有限模型的悲观最优预算集合，不挑一个最好看的权重。目标为质量减去Token/1000代价与支付代价；权重网格均为0、0.01、0.1。该扫描属于探索分析，不是预注册的部署合同。

这依然是潜在报告回放：规范策略的均衡性质可以审计，LLM自主行动与实时端到端协议尚未由此验证。有限开发样本估计出的最优，不能扩大为真实分布或所有连续合同的全局最优。

## 7. 尚未完成的验收项

1. 根据修复后的开发结果审计真实成本尺度，冻结主目标、预算与资源账户语义。
2. 用独立开发问题选定一个合同，随后锁定新测试问题与协议。
3. 实际按公开合同运行局部更新、真实获取、报告和结算，核对离线预测与在线执行；计入选择及协调开销。
4. 自主LLM行为单列测试，不用规范策略的零后悔冒充模型理性。
5. 加入同信息预算的集中式、固定配额和随机基线，比较质量成本，而不只比较获取率。

原论文、专利与正式结论暂不写入新增机制有效性主张。

## 8. 修复版完成结果

v3的72次API采集全部完成：0份格式失败、0份截断、10份弃答；62,447 Token，请求耗时合计123.10秒。本轮v2+v3共144次成功API响应，合计108,913 Token；另有一次受限网络连接失败，单独保留错误记录。

| 预算B | 固定轮转终点的开发集体正确率 | 每题重放报告Token均值 |
|---|---:|---:|
| 0 | 50.00% | 1,480.25 |
| 0.5 | 50.00% | 1,480.25 |
| 1 | 58.33% | 2,594.50 |
| 2 | 58.33% | 2,612.00 |
| 4 | 41.67% | 3,723.67 |

分母为6题各2次潜在结果重放，不是12道独立问题。表中的Token是选中报告调用的计费Token之和，不包括历史来源建库，也不等于全部采集成本。所有Nash配置上的质量上下界在该样本中恰好相同，不代表一般不存在多均衡差异。

在质量−0.01×Token/1000−0.01×支付这一探索目标下，有限估计模型唯一最优预算为B=1；增加成本/支付权重时，最优变为不诱导获取的B=0或0.5。因此不存在不依赖Leader偏好的“普遍最优预算”。这里的权重敏感性是开发分析，不追称预注册确认。

这完成了规范策略求解、来源读取与报告潜在结果的开发联调；尚未完成同一次实际在线运行中的合同承诺—行动—报告全链闭环，也未完成独立测试或自主LLM响应验证。
