# 同模型机制验证：文献调研与方向建议

日期：2026-10-24。性质：研究建议，不是预注册或已验证方法。本轮不调用付费模型，不改冻结实验、原始标签、论文、专利或系统。

## 一、判断

应采用多个能力层次的后端分别做同模型对照，而非弱模型基线对强模型机制组。每个后端内部固定模型、思考模式、信息权限，比较相同机制与简单策略。模型能力次序先由独立开发集确定，不按产品名称或测试结果挑选。当前可用的GLM与DeepSeek只是两个待测后端；不使用Qwen。

旧450题的14.22个百分点只能保留为执行配置联合收益。它不能预先充当新同模型实验的预期效应，也不能用于估计机制净增益所需样本量。新18题加权失败、小样本审阅无增量也不能直接推断所有同模型机制均无效。

建议的顺序是：先用同模型分解核查旧方案；若结构化信息生产仍有信号，再深化其具体过程规则；若没有，不再以旧提升维护四字段，转入一个明确的新假设——预算约束下的证据核查与结论更新。后一项仍需通过小样本可行性验证，不许直接宣布成立。

## 二、优先借鉴的原始研究

以下区分已发表工作与新预印本。检索不能保证穷尽；不能据此宣布创新空白。摘要级阅读与方法、附录核查分别标明。

### 1. 公平参照与独立判断

- [Self-Consistency，ICLR 2023](https://arxiv.org/abs/2203.11171)：多次采样与答案聚合是已有强基线。本轮核对摘要。我们的多Agent机制必须超过同模型、可比预算的独立采样，而不只超过单次简短回答。
- [Voting or Consensus?，ACL Findings 2025](https://aclanthology.org/2025.findings-acl.606/)：通过控制决策协议研究差异，提出独立起草等方法。本轮核对官方摘要。借鉴单因素控制，不能把独立起草本身当成新贡献。
- [Debate or Vote，NeurIPS 2025](https://arxiv.org/html/2508.17536v2)：核查理论与干预章节。多数投票是强参照；其鞅结论依赖特定生成与更新假设，不能扩展为所有真实LLM讨论均无效。Oracle干预与可部署策略必须分列。

### 2. 避免把同源重述当核查

- [Chain-of-Verification，ACL Findings 2024](https://aclanthology.org/2024.findings-acl.212/)：官方摘要中的关键设计是让核查问题独立作答，降低对原答案的锚定。借鉴上下文隔离，不宣称其必然提供外部事实。
- [Large Language Models Cannot Self-Correct Reasoning Yet，ICLR 2024](https://openreview.net/forum?id=IkmD3fKBPQ)：本轮核对原始摘要及评审页。缺少外部反馈的自我纠正可能不增反降；不能把其特定模型任务结果理解为所有自纠均不可能。
- [Tool-MAD，2026预印本](https://arxiv.org/html/2601.04742v1)：核查工具、模型、数据及结果表，使用检索和工具扩展信息来源。借鉴真实信息行动，不照搬多模块堆叠。其跨模型参照表不是对所有模型分别完整施加同一机制；不能引用成“强弱模型上均已隔离证明”。

### 3. 置信度、预算与正确少数

- [Adaptive-Consistency，EMNLP 2023](https://aclanthology.org/2023.emnlp-main.761/)：官方摘要给出基于一致程度的动态停止。它是我们选择性投入必须比较的基线，不能把减少调用本身当新方法。
- [Scaling LLM Test-Time Compute Optimally，ICLR 2025](https://arxiv.org/html/2408.03314v1)：核查难度估计及附录。不同问题适合不同计算策略，但部分难度估计昂贵，研究未完整计入该开销。我们的调度与校准开销必须计入，不能直接照搬其效率数字。
- [Demystifying Multi-Agent Debate，2026预印本](https://arxiv.org/html/2601.19921v1)：核查方法与训练附录。置信度调制依赖校准及训练；附录包含SFT、GRPO，不能误读成API里多加一个置信度字段就有同样效果。候选池扩张的生成成本也应计入。
- [Minority Sentinel，SIGIR 2026 AgentSearch工作坊/预印本](https://arxiv.org/html/2606.29270v1)：核查方法和评测，使用审议特征与分类器选择性翻转多数，强调纠正减退化。存在按数据集优化阈值等设置；我们不采用测试集或各领域事后阈值，须用嵌套开发流程及独立测试。
- [When Debate Helps，2026-10预印本](https://arxiv.org/html/2610.04686v1)：核查固定候选干预、实验与附录入口。把候选覆盖和读出分开已有直接先例，且包含权重扰动构造Agent。可借鉴固定候选池诊断，不能仅把“覆盖—读出”重新命名当创新，也不直接搬到仅API条件。

### 4. 博弈应该怎样真正进入算法

- [The Consensus Game，ICLR 2024](https://www.mit.edu/~gfarina/2024/consensus_game_iclr24/consensus_game_iclr24.pdf)：核查生成/判别策略、信号博弈及评分方法。它将同一模型的生成和判别分布作为明确策略对象，用数值求解改进排名，不要求宣称LLM天然自利。借鉴“博弈对象—可计算策略—实际决策—效果”一致性。其概率评分接口能否由当前API完整提供尚未核查；口头置信度不是相同输入。直接复现属于基线，不是我们的新贡献，均衡也不自动等于答案正确。
- [Debating with More Persuasive LLMs，ICML 2024](https://proceedings.mlr.press/v235/khan24a.html)：核对官方摘要。强专家、弱裁判及信息不对称有特定设置，不能引用其收益为同模型普通聊天辩论背书。

## 三、结合历史：哪些地方值得做，哪些不值得重复

| 历史观察 | 允许推断 | 不允许推断 |
|---|---|---|
| 旧完整配置提升且模型路径大量切换 | 联合执行配置存在正向结果 | AEIC或激励的独立增益已成立 |
| 24题普通审阅与前提审阅都无新增正确 | 本次同信息审阅没有效果 | 换个审阅名称继续扩样就会有效 |
| 双后端评估18题，DDG覆盖17、最终14 | 存在未兑现的正确候选 | 看见3题后专门优化即可证明泛化 |
| 新18题加权11、等票12 | 当前固定池与权重无优势 | 再调几个全局权重就是机制创新 |
| 思考首批净增8、独立复验净增1 | 资源收益依题组与基线而变 | 首批大增益已稳定复现 |

必须保留这些边界。新方案不能只是把已经失败的前提审阅改名为证据审阅：真正不同处应是可核对的信息入口、隔离的核查上下文、同池干预、总预算对照，而非更多字段。

## 四、先补哪一个实验

### 阶段A：旧方案同模型分解

先在两个后端分别比较：

1. 普通充分推理＋独立投票。
2. AEIC结构化报告＋独立投票。
3. 与第2组相同报告协议，加原方案中实际可执行的规则与行动控制。
4. 同预算单体充分推理，作为资源替代基线。

第1组不能写“刻意简短”来制造差距。各组初始可用信息相同，模型和思考模式不切换。第3组如果只是奖励提示、没有真实行动差异，不构成激励有效性实验，应如实取消“博弈”命名；应先列明其相对第2组到底改了哪些执行路径。不得在实现前填上一个笼统的“我们的机制”。

同时报告两类对照：固定权限/上限的总体策略效果；不同预算点上的准确率—成本曲线。相同上限不等于实际Token相等，使用更多输入上下文也有成本，API Token不是跨后端等价FLOPs。不能只事后挑Token碰巧相近的题目。

首先做冻结的小型开发/可行性批次，检查解析、动作差异和估计方差；它不是正式显著性证明。正式样本量根据独立试验估计的配对纠正/退化率及最小有意义效应设计，不承诺60或120题一定足够。所有已查看题组标记为开发证据，独立测试预先固定且只开一次。

### 阶段B：只在必要时深化一个窄假设

若AEIC格式本身无增益，建议把方法目标改为：**预算约束下，利用可追溯证据控制争议核查与答案更新，减少有害改判。** 这是一个待验证方向，不是当前已有机制的成果。

最小流程：独立回答封存 → 抽取可检验的决定性主张 → 在不见票数、模型身份和多数结论的独立上下文核查 → 关联证据/检查结果 → 更新或保持结论。

不强制四字段。理由、主张与证据ID用于实际决策，字段齐全本身不加分。无证据时不能当作反证；检索结果不是自动真值；同一来源的重复引用不是独立证据；一致但共同出错不能靠只触发分歧全部解决。

两步验证，避免再次把检索收益说成机制收益：

- 固定候选和同一证据池，对比普通投票、常规同模型裁判、所提更新规则。这只测读出，不测资源调度。
- 有独立读出信号后，再让所有策略访问相同工具/语料，比较普通单Agent检索核查、固定/随机分配核查、简单一致度触发与所提调度。总成本包括检索、主张抽取、裁判、探测和失败重试。权限相同不要求实际检索结果逐条相同；实际路径差异是策略的一部分。

先选可追溯且与任务相符的信息入口，不引入答案键或官方解释给Agent当工具。需要证据的任务必须明确标成新的开放书/证据核查设置，不能与旧封闭题结果混为同任务提升。可复用通用事实核查任务，不按某类题关键词设计特例。

## 五、强弱模型分层的解释

定义各后端的配对效应 Δ_m = Acc(机制,m) − Acc(强简单基线,m)，同时给成本曲线和题目级区间。

- 两个后端均正向且独立复验：可以讨论跨能力适用性，仍限定测试范围。
- 只在开发集定义的较弱后端有效：可研究能力受限条件，不是假结果；但必须保留较强后端结果，不能写普适优越。
- 只强后端有效：可能依赖核查/工具理解能力，需进一步验证，不能说“强模型更听奖励”。
- 准确率相近但更省：只有事前设定非劣界、充分样本支持且总成本降低，才成立效率贡献；不显著不是等效。
- 两者均无增量：不扩正式大实验，不重新挑模型/题目/阈值解释成成功。

一组显著、另一组不显著不等于组间效应有显著差异；需直接检验 Δ_弱−Δ_强，按原始问题配对重采样。后端之间结果仅用于外部适用性，不合并为“纯能力”因果解释。

## 六、验收与停止

先回答“同模型是否有效”，再回答“什么过程造成增益”，最后才讨论经济激励。需要同时呈现纠正数、退化数、正确候选覆盖、读出损失、格式失败、总Token/调用/延迟；正确候选覆盖仅离线诊断，不是可部署选择器。

新方法必须与最强简单参照比较，不只与故意弱基线比较。若无法超过普通核查或简单分配，停止包装字段/奖励，保留为边界结果。若保留博弈，策略、支付、信息与求解必须是同一个实际算法对象，且求解要提供比直接评分或简单采购更多的价值；不能把过去的性能与另一个游戏的定理拼接。

本轮完成的是文献调研与方向建议，新增模型调用0次。没有证明新机制有效，也没有改动正式研究题目。
