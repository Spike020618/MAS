# 证据贡献博弈v3：统一修订方案与实验执行

日期：2026-10-28。状态：实现与无API验证交付；尚无v3真实效果结果。研究主线仍为“预算约束下基于证据贡献博弈的多智能体共识机制研究”，证据更新与预算协调是同一机制的两个组成部分，不拆成两个独立研究点。

本版针对v2响应与动作空间审查一次收口。保留v2代码、回执和负结果；不把接口修复说成博弈贡献，不承诺正结果。不通过更换测试标签、改成功定义或给博弈独占信息制造提升。

## 一、问题与对应修改

| 已证实的问题 | v3实现 | 验收依据 |
|---|---|---|
| 模型照抄占位主张、具体答案/swap示例 | 去掉完整示例输出，只传字段说明；拒绝已知占位句 | 请求中无schema_example或具体修改样例；原始输出保留 |
| 指定资料已发送，但请求没说清后端引用要求 | assigned_review明确source_id、目标主张和疑问；指令与后端一致 | 每次非放弃修改须引用指定资料，不能替模型换引用ID |
| 引用与核查目标脱节 | 每个目标都需finding，含目标ID、资料ID、判断、原文引文、理由 | 引文逐字存在；support/refute须有目标对应的I边；不支持可unclear |
| 旧资料与新资料混淆 | 本次指派显式命名；后续核查看到此前判断记录 | source_id、当前版本、前后决策、原文引文完整留痕 |
| 另一查询的推荐统计被移作当前资料 | 推荐仅检索本题原有KG、训练聚合与历史卡片；保存conditioned_on_native_id | 不跨查询重绑条件分数；当前对话保留在原prompt |
| 问答混入影片统计、资料包退化 | 问答从已有523万条公开维基资料索引按当前问题检索；不跨任务种类 | 文档不读取答案；输出覆盖诊断与排除名单 |
| 每题3份资料、可查3次，没有选材压力 | 每题最多8份自然检索的不同资料；三份初始分工，最多追加两次 | 仅至少6份不同资料的题进入本轮比较；重复文本不算新资料 |
| 三个Agent实际看相同输入 | 三个初始Agent各看一份不同资料；共同核查阶段再共享其并集与报告 | 独立汇总组不能看到同伴报告；单Agent可依次读取相同三份资料 |
| 学习模型只有结构特征 | 增加查询—标题匹配、检索分数、Agent自身主张—标题匹配、初始分歧等 | 训练与运行调用同一特征函数；无题目/来源身份特征 |
| 两个估计批次对照组结果随机漂移 | 学习估计批复用预设规则批中请求完全相同且完整的回执 | 汇总检查单Agent、独立汇总、固定分配最终决策一致性 |
| 随机拆题与资料隔离目标混淆 | 本轮明确采用原始问题/会话分组留出、共享公开背景 | 不再宣称文档隔离；训练集不含diagnostic题 |

逐字引文只证明“文本确实存在”；判断是否正确、引文是否足以支持推断仍未被自动认证。claim_assessments记录模型对原主张的判断，保留原文以便追溯，不把旧主张静默改写成“已验证事实”。最终答案只经允许的局部补丁改变。

## 二、研究假设与已有调研的继承

待检验的核心假设：真实材料分工产生互补信息；针对疑点追加核查能改善共同决策；在有限预算下，按边际贡献协调核查相对独立汇总、固定指派或简单按分数选择，能获得更好的质量—成本表现。

已有调研中“材料分工”“不强求一致”“保留修正与损害轨迹”“按需交流”的启发继续保留，具体对照与来源见《先进多智能体算法调研与方案修订讨论_2026-10-27.md》。本版是这些原则的项目实现，不声称复现或超越其中论文，也不借他人不同模型/数据集的成绩作直接胜负比较。

博弈不是保证正确的工具。这里运行真实的有限策略效用计算与最佳响应，而不是提示模型“请进行博弈”；仍不等于多个模型通过语言谈判达成博弈均衡。该求解器的收敛不是创新或效果的充分证据。若简单选择足够好，就应承认博弈没有额外价值。

## 三、数据与权限

输入仍为已使用的160道开发任务：StrategyQA 80、ReDial 80。原问题/会话分组hash固定fit/calibration/diagnostic；不会根据本轮答对情况改划分。

检索准备无API、无答案读取。QA使用已有本地5233329条维基资料FTS索引，采用项目已有的标题实体短语检索与BM25回退；BM25标题权重5、正文权重1，取最多10条后按原文去重选8条。默认CLI要求该语料存在，不静默退回几十篇弱缓存；支持显式--corpus路径。保留语料SHA、原始文档ID、标题与原文hash。不同段落不保证信息独立；该工程检索不是语义相关性认证。推荐在本题来源卡片中检索，按证据种类轮换，避免同一种统计占满所有位置；不跨题复制条件分数，也不替换原候选池。

本地完整语料无API检查确认：160题都取得8份不同原文资料，训练拟合分组93题、校准30题、比较37题（QA17、推荐20）。此前小缓存检索的17题覆盖不足问题在本地完整语料中不再出现；仍输出excluded_tasks.json并固定至少6份的覆盖门槛，其他机器或语料若不足必须披露，不为凑数补无关资料、不用其他题顶替。160题只说明词面检索与数量条件通过，不说明每份资料都语义相关。覆盖筛选可能带来选择偏差，不能把结果称为完整StrategyQA或ReDial测试成绩。

训练/校准任务只用于采集、拟合贡献估计；37道比较题不参与这些训练调用。公共文档可以跨分组共享。旧推荐排序器可能训练于这些开发查询，整个系统不能据此宣称完全未见任务泛化；这里主要隔离新增贡献估计的题组，不冒称原生正式测试。

不微调Qwen大模型权重。“训练”仅指拟合一个小型Ridge回归器，预测核查动作的实际净收益。当前只接Qwen Flash，没有跨模型泛化结论。

## 四、统一流程与六种具体做法

每题有同一候选资料池D_q。三次初始调用处理d1、d2、d3，最多两次追加核查；每种做法最多五次逻辑调用、三次初始资料读取加两次追加读取。相同调用上限不等于相同tokens；tokens与已知费用按各组实际回执记账。相同请求被物理复用时，各组逻辑预算仍收费，不能把缓存当某组算法节省。

| 具体做法 | 初始处理 | 追加核查与决策 |
|---|---|---|
| 一个Agent依次阅读并判断 | 同一个Agent按顺序读三份资料，后一次能看到自身此前报告 | 按固定指派最多核查两份；看得到自己的全部历史，形成局部更新 |
| 三个Agent独立核查后汇总 | 每个Agent各读一份，互不看报告 | 预先轮换选两个Agent，各自依据自己的信息选一份未读材料；不共享过程；最后确定性汇总 |
| 按固定规则指派核查 | 各读一份，公开初始报告及三份材料并集 | 与收益无关的稳定hash顺序选择最多两项，保留资料去重与预算约束 |
| 直接按预计净收益选择核查 | 同上 | 直接按Agent—资料的预计净收益排序，忽略共同目标的边际递减，最多选两项 |
| 中央全局优化核查分配 | 同上 | 在与博弈相同的候选、预算和估计目标下枚举最优组合 |
| 边际贡献博弈分配核查 | 同上 | 各Agent根据自身边际贡献改选动作，达到无可行单边收益改进的状态 |

单Agent可读同样的三份初始资料与同一追加资料池，不封锁材料；独立汇总的群体初始读取预算同样是三份。各组允许追加读取上限相同，谁看到了什么、是否重复读取、是否实际发起核查都留下记录。因预算或估计负收益放弃核查应保留，不能给博弈另加调用补齐。

核查流程：指定疑点 → 实际fetch指定资料 → 模型逐目标输出finding → 检查资料权限、引文、目标I边、版本、操作范围 → 应用答案替换或Top10内外候选交换 → 保留原主张与新判断记录。答案/排序不能在report.decision中直接重写。

共同输出是公开初始聚合状态经局部补丁更新后的决策，未解决疑点保留。QA以初始多数聚合，推荐用固定倒数排序融合，所有协作组相同。不把最终大家说得相同当准确率。

## 五、效用、求解与贡献估计

Agent i的策略a_i为“不核查”或一项“资料—目标主张”动作。每个Agent最多一项追加动作，全体最多K=2项；同一原文资料不重复分配；总预计调用费用不超过B=0.02元。成本估计沿用配置式0.003+4×资料字符数×0.15/10^6元，实际费用另记。该成本只是预先估计，不是账单。

令g_hat_i(a)为执行该核查后任务质量变化的预计净收益，已包含错误修改的损害，不再重复扣损害概率。为避免重复累计同一疑点的贡献，把正收益均分至该动作的目标主张。对每个目标c，把分配到它的分量组成V_c：

\[
\Phi(a)=\sum_c\left[\max V_c+\rho\left(\sum_{v\in V_c}v-\max V_c\right)\right]-\lambda\sum_{i:a_i\ne\varnothing}\hat c(a_i),\quad \rho=0.5,\;\lambda=1.
\]

空集合项为0。相同资料在可行性层面禁止重复分配。相同目标的多份不同资料享有递减而非必然为零的贡献；rho是固定的设计假设，不是学习出的最优参数或语义真值。不能声称该式准确恢复真实互补性；用实际结果检验其代理误差。

\[
u_i(a)=\Phi(a)-\Phi(a_{-i},\varnothing).
\]

固定其他Agent时，u_i的变化等于Phi变化。有限动作空间中的严格改进过程终止；共享预算使可行动作依赖别人，输出是共享约束下的广义Nash局部稳定状态，不冒称无约束Nash或全局最优。实现记录每次变更、最大可行偏离和中央最优代理目标差。求解顺序固定0、1、2；顺序敏感性当前不作为新实验矩阵自动扩展。

中央方法直接最大化同一Phi，故博弈不能在该估计目标上优于中央全局最优。实际任务结果可能不同，那是代理误差、执行顺序及模型输出的问题，不是打破最优性。三Agent规模下中央求解本来便宜，不能预设博弈计算效率有优势。

预设规则使用检索相关性和自身初始主张—资料标题匹配；学习方式用同一组动作前特征拟合Ridge(alpha=10)：任务类型、来源种类、长度、检索分数、查询—标题匹配、Agent自身主张—标题匹配、初始分歧、状态版本、可见资料比例等。自身报告明确进入核查请求，不能凭空给Agent乘“专业能力系数”。这些是可观测上下文差异，不是已认证的能力差异。

训练对每题选择稳定hash探索的一项未读动作与一名Agent，记录执行前特征。QA收益为正确性变化，推荐为Recall@10变化；两者均在[-1,1]。模型只使用fit，校准集只估计平均残差偏移；比较题标签不进入模型。操作失败时确实维持原决策的，记实际执行策略的零收益，同时保留invalid，不能把它说成语义无效。初始QA为abstain者不用于贡献拟合，数量另报，避免容易的拒答恢复夸大收益。

## 六、固定实验顺序与停止条件

1. 无API检查。资料按任务种类、当前query、唯一原文、原题组分区检查；输出所有覆盖不足题，不替换样本。
2. 六题真实接口探针。只使用训练侧前三道QA和前三道推荐，总计最多24次调用；这些回执随后原样复用。初始与核查有效率各至少80%才继续。门槛只检查真实主张、指定目标及引用合同，不用答对率、正收益或接受修改次数筛选。允许有效unclear/abstain，不强迫支持与修正。失败自动停止并保留回执，不偷偷改prompt后沿用同一批。
3. 完成123题动作探索并封存，才读取训练标签；拟合与校准贡献模型。
4. 在固定37题上分别比较预设规则与学习贡献；各运行六种具体做法。学习批复用完全相同请求的已有完整回执，避免固定对照漂移；未知计费请求不自动补发。
5. 自动生成报告。先看合同失败、真实引文/unclear/接受更新、改善与损害、成本，再看博弈相对独立汇总/固定/直接按分数选择的差异，以及与中央方法的差距。没有提升照常完整报告，不自动换模型、加样本或优化测试集。
6. 已预写三个干扰环境，作为主批完成后的单独固定命令：移除最高检索分的未读资料；加入两份完全重复原文；加入低词面匹配的静态背景材料。六种做法在同一环境受同样干预，只使用冻结学习模型，不再重训。初始三份资料保持相同，题目/候选/标签不换。低匹配不等于语义无关，必须如此披露。

主结果分别报告QA准确率与推荐Recall@10，不混成总分。所有原定题都保留，失败进入执行效果分母，不只挑双方有效样本。另报告invalid、明确放弃、接受更新、从自身初始状态改善/损害、相对独立汇总按题改善/损害、逻辑调用、实际tokens、物理调用、已知估价与未知计费。

按原始QA题或推荐会话做配对重采样，固定seed=20261028、2000次，报告探索性95%区间；QA同时记录未做多重校正的精确McNemar p值。小开发批、多组比较、旧题复用限制明确存在，不据此宣称统计显著、SOTA或用户满意度提升。固定主要对照为博弈对独立汇总，固定/直接按分数/中央用于机制解释。

若博弈仍与简单方法同效果，只能研究是否节省调用且不增加损害；若仍无这类证据，保留负结论。若核查有效但排序/答案没有增益，检查真实任务信息价值；不继续靠换求解器名称掩盖问题。当前论文可写框架、实现、合同失败诊断、旧负结果与可复现协议，不能把未验证收益写进结论。

## 七、运行命令与恢复

先检查，不付费：

```bash
bash scripts/run_protocol_v3_pipeline.sh experiments/results/protocol_v3_frozen --prepare
```

完整执行（用户运行，包含探针通过后自动继续采集、训练、两批比较及报告）：

```bash
bash scripts/run_protocol_v3_pipeline.sh experiments/results/protocol_v3_frozen --run
```

若只想先运行六题探针：

```bash
bash scripts/run_protocol_v3_pipeline.sh experiments/results/protocol_v3_frozen --probe
```

之后运行同一--run可复用探针，不重复付费。采集上限800次/5元；每个比较批上限1000次/5元。主流程三个阶段合计配置上限15元，不是总共5元；正常实际用量另看回执。干扰三批另有各自5元上限。命令默认只准备，不静默付费。

主批完成后，固定干扰检查：

```bash
bash scripts/run_protocol_v3_stress.sh experiments/results/protocol_v3_frozen --run
```

不改代码和输入时，再执行同一命令会校验计划并复用完整案例或精确请求回执；并发重复启动由锁拒绝。源码、模型或输入不符明确失败；未知请求不自动补发，保留失败记录进入结果。不能把v2目录传给v3，也不能删除失败回执以强制重发。给其他模型接手时先读HANDOFF.md，再读本文及root/plan.json；不凭旧PID猜进度。

最终主报告root/report.md和report.json；逐批summary.json、physical_summary.json；案例在cases、原始回执在slots；模型及训练分组单独保存。干扰结果在root/stress/{missing,redundant,distractor}/summary.json，并生成root/stress_report.md。

## 八、实现对应与验收

- prepare_protocol_v3.py：查询相关、类型分离、当前query条件统计、覆盖诊断与固定分组。
- evidence_consensus/protocol_v3.py：请求、逐目标finding/引文、特征、局部更新。
- evidence_consensus/allocation_v3.py：共同约束、边际贡献博弈、中央枚举、固定与直接选择。
- evidence_consensus/runner_protocol_v3.py：真实分工、六种做法、同调用上限、回执复用、完整封存与评分。
- acquire_protocol_v3.py、fit_protocol_v3.py：训练侧探针、动作探索、标签后读、拟合与校准。
- prepare_protocol_v3_stress.py：三种预先规定的干扰，不改标签或候选。
