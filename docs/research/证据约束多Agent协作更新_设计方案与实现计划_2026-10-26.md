## 1. 已确认的研究边界

用户已确认：

- 多 Agent 协作与证据更新是研究核心，推荐是应用场景；博弈允许作为协调建模，不要求提出新的均衡算法。
- **可靠的证据更新与预算下的核查协调，是同一个研究点的两个组成部分，不拆为两个研究点。** 本文不重新划分整篇毕业论文的另一个研究点。
- 保留五个核心实验条件，其他对照只在需要解释结果时作为后续消融。
- 当前优先收敛方案和工程，不继续以增加预实验数量代替方法收敛。

研究点暂名：**有限预算下证据约束的多 Agent 协作更新机制**。

核心问题：多个 Agent 对互补且可能出错的信息形成局部判断后，能否通过定向交流、证据核查和限定范围的更新，在控制误改与成本的同时改善共同决策？

完整机制链：信息分工 → 初始主张与证据 → 分歧/缺口定位 → 预算协调选择核查 → 三态核验 → 局部状态更新 → 统一决策。

“可靠”是待验证目标，不是现有能力声明；“共识”指可追溯的共同决策过程，不要求所有 Agent 文本或观点一致。

## 4. 研究问题与可证伪假设

这些问题属于同一研究点内部的评价维度。

- RQ1：相比独立汇总和普通交流，证据约束更新能否提高错误处理率，同时降低正确内容被破坏的比例？
- RQ2：集中式单 Agent 拥有相同资源后，多 Agent 协作是否仍有增益，增益体现为质量、成本还是特定任务条件？
- RQ3：同一更新机制下，自适应核查是否比固定调度更有效利用预算，并改善共同推荐决策？

交流的价值不定义为“创造汇总器永远拿不到的信息”。汇总器可能已有全部报告；待检验的是定位遗漏、补查证据、解析冲突和正确落实更新的能力。

假设分别对应纠错/保真、协作必要性和协调价值。允许其中部分不成立；不得用一个指标的成功替代另一假设。

## 6. 状态、核验与决策接口

状态至少包含不可改写的原始观察、主张类型/所有者/候选绑定、证据引用、版本哈希、核验记录、依赖关系和追加式事件日志。

初始主张是未经核实的主张。核验失败、证据不足和尚未核验分别记录，不因回退而混成一个成功判断。

更新操作：

- keep：支持目标主张，保留其有效状态。
- retract：反驳目标主张，使其退出有效状态。
- defer：不足以支持或反驳，保留未决状态，不能据此增加确定性约束。
- replace：旧主张被反驳且替代主张得到支持后，原子地撤旧立新；不满足前提时保留拒绝原因。

每次操作绑定精确目标和当前版本，只更新目标及其依赖。依赖失效必须进入最终决策输入，不能仅在日志中删除一句解释。跨所有者挑战允许，但修改须通过统一状态接口，不允许绕过归属和版本校验。

最终聚合器对五个条件使用相同基础实现、候选规则和输出上限；输入为各条件产生的有效状态。初始排名是否输入必须统一并冻结，禁止仅给部分方法额外锚点。未决预测可以按统一规则参与软判断，不能被提升为硬事实；只有明确有效的硬约束才允许筛除候选。事实被撤销不等于整部影片失去相关性。

所有方法使用统一日志与解析规则；普通交流允许整报告修订时，保留其原生自由度，并通过外部差异追踪计算误改，不能暗中给它完整范围门控。

## 7. 预算协调与博弈建模

协调是本机制的一部分，不单列为另一个研究点。

最小动作：选择一个待处理目标及负责角色，执行一次证据补查/核验/更新，或者停止。已处理且无新证据的相同目标不重复收费核查。所有模型调用、工具操作、失败及重试均进入预算账本。

固定调度采用预定轮转顺序；自适应调度采用可解释的优先级。候选特征限于运行时可观察量：明确冲突、证据缺失、主张与候选决策的依赖、预计动作成本、已核查情况。不使用未来标签，也不把模型自报置信度当校准正确概率。

优先级可写为 P(a|S)=wᵀx(a,S)−λ c_hat(a)。这是排序启发式，不等于已估计的期望准确率增益。特征定义、权重和成本估计在开发侧确定并冻结；初版不引入额外模型为每个动作估值，以免调度开销吞没收益。组合互补动作可能被单步策略遗漏，该限制单独报告。

博弈描述：Agent 在共享信息状态和资源约束下选择信息处理动作，以共同决策效用扣除资源成本为团队目标。真实任务效用仅用于离线评价，在线策略依据可观察代理量协调。有限预算提供执行上界；固定代理收益下的性质不自动适用于状态随证据变化的过程。

本版不声称求出纳什均衡、全局最优或证明实际推荐增益；若未实现博弈求解，只能称“合作博弈视角下的协调策略”。不得把启发式调度包装成均衡求解算法。

## 8. 五个核心条件

| ID | 条件 | 允许行为 | 主要比较 |
|---|---|---|---|
| C0 | 独立报告＋统一汇总 | 读取全部初始报告后直接决策 | 初始集成起点 |
| C1 | 普通同伴交流 | 同伴审阅与整报告修订，使用相同证据/核验服务权限，不强制局部三态更新 | 普通交流是否足够 |
| C2 | 集中式单 Agent | 连续工作记忆、相同原始资料/工具/核验服务和预算，无角色隔离 | 协作组织的必要性 |
| C3 | 证据约束协作＋固定调度 | 完整状态更新，预定轮转核查 | 更新机制与普通交流比较 |
| C4 | 证据约束协作＋自适应协调 | 与 C3 相同，仅改变动作选择和停止 | 协调的增量 |

核心对比：C3−C1 是更新机制整体的比较，不足以单独识别其中每个组件；C4−C3 识别调度策略差异；C4−C2 检验整体相对集中组织的价值；C1−C0 描述普通交互增量但包含额外计算影响。

自审、去核验、去范围、强制二元保留为后续解释性消融，不全部默认进入正式矩阵。不能用 C3−C1 的效果宣称“范围约束单独有效”。

### 两层公平性

机制层：共享冻结初始报告；比较共同可见的证据/反馈下的更新。固定反馈回放适合测试更新规则；有动作选择差异时允许不同实际查询，但开放相同查询权限。不能把离线共享全量反馈的实验用于证明在线核查节省成本。

端到端层：各条件自行处理相同原始输入，统一模型、工具、候选、预算上限和决策器。C2 不被迫模拟三个角色；它能自主使用预算和连续历史。共享初始报告条件下的 C2 只回答集中更新能力，不能替代独立端到端单 Agent 对照。

共同预算上限不等于实际成本相同。报告质量—成本曲线及预算档位；C0 是低成本起点，不能据 C4 优于 C0 就声称纯协作增益。共享请求逐方法计入逻辑成本，物理消费去重，调度/核验/聚合/失败重试均计费。

## 9. 评价设计与无人工标注约束

### 9.1 三层证据

A. 工程不变量：结构、哈希、归属、范围、状态、续跑和账本；可以确定性验证，但不能代表语义效果。

B. 受控机制实验：根据独立来源或构造规则产生可判定支持/反驳/不足的主张；包含正确对照、错误事实、否定/主体/时间、冲突来源和证据不足。正误扰动只作用于观察/报告，评价真值与推理输入物理隔离。补查池必须有机会找到证据，也保留确实不可判定案例。

C. 自然推荐任务：独立留出数据上的任务指标与成本。核验器输出不作为真实主张标签；没有人工金标准时，对自然语义的分析只能报告代理评价及局限。

人工盲标当前不可行，不作为全部工程的硬阻塞。主张级可信结论优先来自受控和可确定性核对的子集；独立模型/NLI辅助审计应尽量避开运行时核验器，但即便换模型仍不是金标准。以前69条盲标包保留为未完成资产，不声称已被自动代理等价替代。

### 9.2 指标与分析单位

- 纠错：原错误主张得到正确撤销/替换的比例；支持/反驳/不足三态混淆矩阵。
- 保真：原正确主张的保留率和误改率；不足主张被错误确定的比例。
- 执行：核验到实际状态的一致率、越界修改、过期版本、证据引用失败、有效完成率。
- 交流：定位了哪些原汇总遗漏、使用了哪些补充证据、更新是否实际进入决策；文本引用数和报告新颖度不当作有效信息量。
- 任务：建议固定候选 Hit@5 为单目标找回主指标；多目标样本需提前规定相关集合及 Recall/NDCG定义，不在看结果后切换主指标。显式约束合规单独报告，不能替代找回收益。
- 成本：实际 token、请求、工具次数、延迟、成功/失败与逻辑/物理成本；无账单时不虚构货币费用。

按对话/用户/上下文组处理依赖，不能把同一证据的多个扰动当独立样本。配对比较报告效果差、置信区间和改善/损害数量；二元指标使用适当配对检验，多个主要比较预设校正。样本量依据开发侧可检测差异与预算估计，不无限追加直到显著。

全部样本的执行结果与双方有效配对子集同时披露。预设超时/无效后的共同回退策略，失败算入系统表现；有效配对仅作敏感性分析，不能删除失败后成为唯一主结果。

## 13. 停止规则与结论边界

- 工程失败在方法间明显不均衡：修复可比性，不作效果归因。
- 纠错改善但推荐不改善：报告证据状态收益，检查决策相关性，不宣称推荐有效。
- C4与C2持平：多 Agent额外价值未成立；可保留适用条件或成本发现，不用核验收益替代协作收益。
- C4与C3持平：协调增量未成立，优先保留简单调度，不继续为复杂度找理由。
- C3与C1持平：更新机制整体优势未成立；按预定误改/不足指标解释，不事后换终点。
- 结果混合：报告改善与损害、适用边界；不依据测试结果重选样本或重定义成功。

只有冻结后的独立评价支持效果结论。研究创新候选是可执行的协作更新与协调闭环及其证据，而不是模块名组合、角色数量、已有博弈定理或历史最好成绩。
