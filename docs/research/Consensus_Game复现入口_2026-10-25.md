## 旧实现不能代替原文的原因

| 项目 | 旧原型 | 本轮要求 |
|---|---|---|
| 更新 | 交替精确最优响应 | 两方基于相同历史同步 piKL |
| 局部收益 | 自定义类型/候选权重 | 原文 Q_G、Q_D 中的 1/2 系数 |
| 参数 | 默认正则 0.5 | 原文四参数默认均 0.1 |
| 输入 | API 返回 A/B 单 Token 概率 | 完整候选文本的条件似然及必要背景似然校正 |
| 理论 | 特定加权势博弈数值残差 | 区分平均相关分布的结论与末次策略实证稳定 |

不能根据旧原型失败否定原文，也不能把新求解器接到旧编码概率后宣称忠实复现。完整文本似然不能由少数 top-logprobs、缺失值补零或模型自报概率替代。

## 实施顺序及停止条件

1. 接口门：检查现有后端是否支持对指定完整候选文本逐 Token 评分，并覆盖正/负生成、候选核验及相应背景输入。当前未确认支持。若不支持，明确标记 API 限制；另行选择可评分的开放权重后端，不自动下载大模型或使用 Qwen。
2. 数值门：与作者公开实现或独立逐式计算对齐初始化、同步顺序、5000 次迭代索引、最终读出、任务级似然校正。当前只有逐式单步测试，不冒充作者复现验收。
3. 开发门：相同模型、候选集、原始评分记录，同时比较 G、D、SC、MI、ER-G、ER-D；若另做多采样，比较同候选多数投票。记录全部模型调用、Token 与离线求解时间；不把离线迭代算成 API 调用。
4. 独立门：锁定规则后使用未进入开发的新题；保留模型版本、来源隔离、配对统计及简单基线。没有增量不扩样、不换指标制造正结果。

## 下一条研究假设：不是当前贡献

ECON（ICML 2025）可作为可学习协调的参照：固定模型 API，训练额外信念/控制网络，改变真实生成行动。先核对作者代码、训练反馈、算力及 API 参数兼容，再决定是否复现。
https://proceedings.mlr.press/v267/yi25c.html
https://github.com/tmlr-group/ECON

即便该路线有效，也必须比较普通非博弈控制器和同预算搜索，不能把训练、采样参数优化或额外计算的收益直接归因于均衡。旧 450 题配置收益仍独立保存，不与新方法定理拼接。
