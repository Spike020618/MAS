## 0. 协议地位与边界

### 0.1 一个研究点，两个组成部分

本研究点暂名：**有限预算下证据约束的多 Agent 协作更新机制**。

它包含两个组成部分，但不拆成两个研究点：

1. **可靠的证据更新**：主张与证据绑定、分歧定位、三态核验、限定范围的局部更新，目标是在纠正错误的同时不破坏正确内容。
2. **预算下的核查协调**：在有限调用和 token 约束下，选择下一步核查哪个目标、何时停止，目标是让同样的预算处理更有决策价值的问题。

博弈只作为协调建模：Agent 共享决策目标与信息状态，在资源约束下选择核查动作；团队收益是共同决策质量扣除资源成本。本文不提出新的均衡概念，不声称求出纳什均衡或全局最优，也不把启发式调度包装成博弈求解算法。

### 0.2 冻结与待定的分界

本协议当前冻结：

- 任务与数据入口；
- 三角色的信息职责；
- 四类主张及其可核验边界；
- 状态机与更新合同；
- 五个核心条件及其公平性规则；
- 工程批的案例、模型请求参数、预算上限、调度规则和验收门；
- 评价指标、分析单位、失败处理与停止规则。

本协议明确留待后续冻结：

- 确认性样本量与统计功效；
- 107 例未使用 dev 的开发/留出划分；

- Gate 2 受控语料的最终版本与分组；

这些待定项不阻塞工程门；在对应阶段开始前必须单独写入手册并冻结，不能边看结果边补参数。

### 0.3 本协议不声称什么

- 不把合成受控语义当成真实对话的语义准确率；
- 不把工程批的 3 例当成推荐效果或效率证据；
- 不把“核验收益”当成“多 Agent 协作收益”；
- 不把 C3−C1 的差异归因于范围约束中的某一个组件；
- 不把固定候选内的 Hit@5 当成真实用户满意度；
- 不把自适应调度称为均衡求解；
- 不把本协议与 AgentCF 式训练时记忆更新、MovieLens 历史排序或旧 450 题结果混池。

## 1. 研究问题与可证伪假设

### 1.1 核心问题

多个 Agent 对互补且可能出错的信息形成局部判断后，能否通过定向交流、证据核查和限定范围的更新，在控制误改与成本的同时改善共同决策？

交流的价值不定义为“创造汇总器永远拿不到的信息”。汇总器可能已经拥有全部初始报告；待检验的是交流与更新能否定位独立汇总遗漏的冲突和证据缺口，补查证据，并把修正正确落实到最终决策。

### 1.2 假设

| 编号 | 假设 | 主要比较 | 主要指标 |
|---|---|---|---|
| H1 | 证据约束更新比普通同伴交流更能纠正错误主张，同时更少破坏正确主张 | C3 vs C1 | 纠错率、误改率、三态混淆、状态执行一致率 |
| H2 | 在相同信息、工具、核验服务和预算下，多 Agent 协作相对集中式单 Agent 仍有增益 | C4 vs C2 | 决策质量、实际成本、失败率 |
| H3 | 自适应核查比固定调度更有效地利用同一预算 | C4 vs C3 | 决策质量、有效核查数、实际成本 |

H0 对应的可能结果：H1、H2、H3 中任意一项不成立。协议允许负结果，且不得用另一个指标的成功替代未成立的假设。

## 2. 任务、数据与信息权限

### 2.1 主任务

沿用 ReDial 对话前缀与固定候选推荐流程：

- 只读取推荐时点之前的对话和合法训练资料；
- 固定 100 候选池，候选来自既有 label-free hybrid retrieval 顺序，不注入目标；
- 未来电影提及和点赞标签只用于离线评价，不进入任何运行时输入；
- 主指标为固定候选内 Hit@5，针对冻结的 eligible target set；
- 候选生成方法、目标是否用于构造候选、命中覆盖必须随结果披露；
- 不把对话前缀伪装成长周期用户画像；没有训练协同数据时不虚构协同 Agent。

### 2.2 数据划分

| 划分 | 规模 | 本协议用途 | 标签状态 |
|---|---:|---|---|
| train | 4,677 请求 / 547 参与者 | 只用于既有候选构造与历史资料，不进入当前更新实验 | 不用于当前评价 |
| dev | 167 请求 / 68 参与者 | 工程、机制和开发阶段 | 仅离线评分；运行时不可见 |
| dev: engineering | 12 例，本批取前 3 例：5431、13554、11960 | Gate 1 工程批 | 不读取 |
| dev: v4 pilot | 48 例 | 已用于 v4/v5 开发，不作为确认性样本 | 不追溯修改 |
| dev: unused | 107 例 | Gate 2/Gate 3 开发池候选；划分待冻结 | 冻结前不读取 |
| reserved_test | 60 请求 / 27 参与者 | 最终确认，当前封存 | 未读取、未评分 |

审计事实：`worker_overlap` 在 train/dev、train/reserved_test、dev/reserved_test 之间均为 0；`reserved_labels_read_by_auditor=false`；`sample_selection` 为固定哈希顺序，不按基线错误或冲突挑选。以上来自 `development_retrieval_audit.json`，不重新解释为真实用户隔离或全新测试集。

### 2.3 信息权限

每个方法只能看到：

- `case_id`；
- `observations`（对话前缀中的可追溯发言）；
- `previous_mentions_excluded_not_asserted_seen`（明确排除“提及即看过”的字段）；
- `candidates_in_shared_retrieval_order`（固定候选的结构化字段）；
- 自己产生的报告、状态和核验反馈。

禁止出现：评价标签、reserved_test 内容、未来电影提及、方法臂身份、最终排名、命中结果、他方法的私有状态。

三角色与集中式控制器拥有相同的原始信息、工具和核验服务权限。角色分工不得制造基线无法访问的资料。

## 3. 角色与主张类型

### 3.1 角色

| 角色 | 信息职责 | 主要产出 |
|---|---|---|
| `current_request` | 当前请求中的明确偏好、排除项、条件与否定 | 带原文证据的主张 |
| `history_applicability` | 历史偏好在当前时点的适用性、时序与主体归属 | 带适用条件的主张 |
| `movie_fit` | 候选物品属性与当前请求的匹配 | 带候选绑定的主张 |

物品结构化字段直接读取；模型只承担需要语义解释的任务。三个角色不是 MACRec/AgentCF 原角色复刻，也不因数量本身构成协作价值。

### 3.2 主张类型

| 类型 | 例子 | 合法判断 |
|---|---|---|
| `item_fact` | 影片年份、类型 | 相对于给定来源支持/反驳/证据不足 |
| `explicit_preference` | 用户本轮明确排除恐怖片 | 对照主体、否定、时序、适用范围 |
| `preference_hypothesis` | 用户可能喜欢慢节奏电影 | 标记假设与依据，不交给事实核验器判真伪 |
| `recommendation_prediction` | A 比 B 更值得推荐 | 由独立任务评价检验，不标记为已核实事实 |

硬约束：

- 每份报告最多 3 条主张；
- 主张 ID 为本地 ID，不含冒号；运行时注册为 `owner:claim_id`；
- 依赖必须是已存在的限定 ID，禁止环；
- 主张必须绑定 `source_ids` 与 `candidate_ids`；
- 初始报告中的 `updates` 必须为空；
- 预测和假设不得被提升为硬事实，不得据此筛除候选。

## 4. 状态机与更新合同

### 4.1 状态

| 状态 | 含义 |
|---|---|
| `unverified` | 事实/明确偏好主张尚未核验 |
| `hypothesis` | 偏好假设或推荐预测，不进入事实核验 |
| `supported` | 核验为支持，可作为有效证据 |
| `retracted` | 核验为反驳，退出有效状态 |
| `unresolved` | 证据不足，保留不确定性 |
| `invalidated` | 自身未被反驳，但依赖前提失效 |

`retracted` 主张不得再次被修改；`invalidated` 不是反命题，只是不能作为有效输入。

### 4.2 操作

| 操作 | 前提 | 效果 |
|---|---|---|
| `keep` | 核验为支持 | 主张保持有效 |
| `retract` | 核验为反驳 | 主张退出有效状态 |
| `defer` | 证据不足 | 保留未决，不增加确定性约束 |
| `replace` | 旧主张被反驳且替代主张被支持 | 原子撤旧立新 |

### 4.3 不变式

1. 每次操作绑定精确目标和当前 `expected_hash`；哈希不匹配即拒绝。
2. `replace` 只能修改 `text`、`source_ids`、`stance`；`claim_id`、`candidate_ids`、`claim_type`、`depends_on` 必须保持不变。
3. 在被反驳旧主张上提出替换、但替代主张未获支持时，整个操作拒绝，状态不变。
4. 只更新目标及其直接/传递依赖；不允许借机重写整份报告。
5. 依赖前提被撤销或失效时，下游主张进入 `invalidated`，并且这一变化必须进入最终决策输入，不能只留在日志里。
6. 普通同伴和集中式控制器允许整报告修订，保留其原生自由度；不得暗中给它完整范围门控。
7. 所有拒绝、失败、重试和未知计费都进入账本；不自动修补解析结果、不自动补字段、不自动重试。
8. 最终聚合只读当前有效状态；被撤销主张不提供支持；未决/假设按统一软规则参与，不能被提升为硬事实。

## 5. 五个核心条件与公平性

### 5.1 条件

| ID | 条件 | 允许行为 | 主要比较 |
|---|---|---|---|
| C0 | 独立报告＋统一汇总 | 读取全部初始报告后直接决策 | 初始集成起点 |
| C1 | 普通同伴交流 | 同伴审阅与整报告修订；相同证据/核验服务权限；不强制局部三态更新 | 普通交流是否足够 |
| C2 | 集中式单 Agent | 连续工作记忆、相同原始资料/工具/核验服务和预算；无角色隔离 | 协作组织的必要性 |
| C3 | 证据约束协作＋固定调度 | 完整状态更新，预定轮转核查 | 更新机制与普通交流比较 |
| C4 | 证据约束协作＋自适应协调 | 与 C3 相同，仅改变动作选择和停止 | 协调的增量 |

### 5.2 主要比较

- **C3−C1**：更新机制整体相对普通交流；这是机制比较，不足以单独识别范围约束、三态核验或依赖失效中的某一个组件。
- **C4−C3**：自适应调度相对固定轮转；只改变动作选择与停止。
- **C4−C2**：协作组织相对集中式单 Agent；检验多 Agent 的额外价值。
- **C1−C0**：普通交互的描述性增量，包含额外计算影响，不作纯协作因果结论。

自审、去运行时核验、去范围约束、强制二元保留为解释性消融，不默认进入正式矩阵；不得用 C3−C1 的效果宣称“范围约束单独有效”。

### 5.3 两层公平性

| 层 | 初始报告 | 回答什么 | 本协议位置 |
|---|---|---|---|
| 机制层 | 五个条件共享冻结初始报告 | 在共同可见信息下，更新与协调本身是否有效 | Gate 1 工程批、Gate 2 机制门 |
| 端到端层 | 各条件自行处理原始输入 | 整体组织方式是否有实用价值 | Gate 3 必须包含；当前工程批不覆盖 |

集中式单 Agent 在机制层获得同一份共享初始报告、连续审阅历史、全部原始证据和相同核验反馈；端到端层不强迫它模拟三个角色，允许它自主使用预算和连续历史。

共享初始生成与核验反馈按逻辑路径计费；物理请求去重；实际 token 与请求数分别报告。共同预算上限不等于实际花费相同，不能只比较最高准确率。

## 6. 预算与协调

### 6.1 动作

最小动作集合：

1. 选择一个待处理目标及负责角色；
2. 执行一次证据补查/核验/更新；
3. 停止，把预算留给最终聚合。

已处理且无新证据的相同目标不重复收费核查；相同 `claim_hash` 的核验结果缓存复用。

### 6.2 工程批冻结预算

| 参数 | 值 |
|---|---:|
| 每路径最大逻辑调用 | 20 |
| 每路径最大证据核查 | 6 |
| 单次最大 prompt token | 64,000 |
| 单次最大 completion token | 1,280 |
| 每路径 prompt 总量 | 640,000 |
| 每路径 completion 总量 | 25,600 |
| 最大轮数 | 3 |
| 批次最大物理尝试 | 150 |
| 请求模型 | `deepseek-chat` |
| 温度 | 0 |
| 输出格式 | JSON object |

工程批 3 例 × 5 条件 = 15 条路径。任何路径超出上限即失败，不能绕过预算。

### 6.3 固定调度

按 owner 轮转、主张字典序选择；已处理目标跳过。固定调度的作用是提供可复现的基准，不声称最优。

### 6.4 自适应调度

只使用运行时可观察量：

- 明确立场冲突：2 分；
- 立场不确定：1 分；
- 初始排名分歧：1 分；
- 存在依赖下游：1 分。

同分按字典序；单步动作成本视为相同，实际复合成本单独记账；不引入额外模型为动作估值，不使用未来标签，不把模型自报置信度当校准概率。

优先级公式是排序启发式，不是期望准确率增益估计。组合互补动作可能被单步策略遗漏，这一限制必须单独报告。

### 6.5 博弈建模边界

- 收益：团队共同决策效用扣除资源成本；在线策略只依据可观察代理量。
- 策略：选择目标、核查、更新、停止的规则。
- 求解：本版不求解均衡，只执行并评价协调策略。
- 若未实现博弈求解，只能称“合作博弈视角下的协调策略”，不得称均衡算法。

## 7. 评价

### 7.1 三层证据

| 层 | 内容 | 能支持什么 | 不能支持什么 |
|---|---|---|---|
| A 工程不变量 | 结构、哈希、归属、范围、状态、续跑、账本 | 可执行性与可比性 | 语义效果 |
| B 受控机制 | 构造可判定的支持/反驳/不足案例 | 纠错、保真、执行一致性 | 真实自然语言准确率 |
| C 自然推荐 | 独立留出数据上的任务指标与成本 | 任务收益与成本 | 核验器输出即真值 |

人工盲标当前不可行，不作为全部工程的硬阻塞。代理评审必须标为模型代理，不能称人工金标准。

### 7.2 指标

| 维度 | 指标 |
|---|---|
| 纠错 | 原错误主张被正确撤销/替换的比例；三态混淆矩阵 |
| 保真 | 原正确主张保留率；误改率；证据不足被错误确定的比例 |
| 执行 | 核验判断与实际状态一致率；越界修改；过期版本；证据引用失败；有效完成率 |
| 交流 | 定位了哪些独立汇总遗漏的冲突/缺口；使用了哪些补充证据；更新是否实际进入决策 |
| 任务 | 固定候选 Hit@5 为主；显式约束合规单独报告；多目标样本提前冻结 Recall/NDCG 定义 |
| 成本 | 实际 token、请求、工具次数、延迟、成功/失败；逻辑与物理成本分列；无账单不虚构货币费用 |

文本引用数、报告长度和新颖度不当作有效信息量。

### 7.3 统计

- 分析单位是对话/上下文组，不把同一证据的多个扰动当独立样本；
- 配对比较报告效果差、置信区间、改善与损害数量；
- 二元指标使用配对检验（Gate 3 主比较用精确 McNemar）；
- 三个主要比较使用 Holm–Bonferroni 校正，α=0.05；
- 全部执行样本与双方有效配对子集同时披露；失败计入系统表现，不能删除失败后把有效配对当唯一主结果；
- 样本量按开发侧配对差异估计，不无限追加直到显著。

### Gate 2：机制门

#### 2A 语料

| 子集 | 规模 | 来源 | 用途 |
|---|---:|---|---|
| 确定性目录事实 | 离线门已构造 54 例 / 18 组；Gate 2 正式版待重建 | 离线版来自工程 3 例；正式版从未使用 dev 重建 | 状态机执行正确性 |
| 受控语义校准 | 84 题 / 28 组 / 7 类 | 既有合成模板 | 三态核验校准；不称真实对话准确率 |
| 明确偏好/否定/时序/主体 | 含在 84 题内 | 合成模板 | 明确偏好与事实边界 |

受控语义校准的 84 题已经在 v5.1 使用过；Gate 2 只能把它作为回归校准，不得当作新的独立证据。正式机制语料需要用未使用 dev 重建并重新冻结版本。

#### 2B 有效性门槛

| 检查 | 门槛 |
|---|---|
| 确定性目录事实动作正确率 | 100% |
| 核验判断与状态执行一致率 | 100% |
| 三态总准确率 | ≥0.90 |
| 每类召回 | ≥0.80 |
| 每类别准确率 | ≥0.75 |
| 错误支持（false supported） | 0 |

这些是“机制是否可信到可以进入效果评价”的门槛，不是“机制是否有效”的成功门槛。未通过时停在 Gate 2，修复或重设版本，不进入 Gate 3。

#### 2C 效果指标

报告但不设正向通过门槛：

- 错误主张正确处理率；
- 正确主张误改率；
- 证据不足时错误下定论率；
- 冲突/缺口定位率；
- 有效核查数与实际成本；
- 按上下文组的配对差异与置信区间。

若 C3 的误改率高于 C1 的 95% 置信区间上限，暂停并诊断误改来源，不进入 Gate 3。

### Gate 3：推荐效果与协调价值

#### 3A 数据

- 从 107 例未使用 dev 中按 case_id 哈希固定划分开发/留出；具体比例和清单在确认性协议中冻结；
- 60 例 reserved_test / 27 参与者只在最终确认阶段启用，启用前不读标签、不评分；
- 12 例工程案例和 48 例 v4 pilot 不进入确认性样本；
- 沿用固定 100 候选、同一模型、同一候选规则、同一输出上限。

#### 3B 主要比较

| 比较 | 回答 |
|---|---|
| C3 vs C1 | 更新机制是否优于普通交流 |
| C4 vs C3 | 自适应协调是否优于固定调度 |
| C4 vs C2 | 多 Agent 协作是否优于同资源集中式单 Agent |

C1 vs C0 作为描述性起点；所有主要比较使用配对设计、精确 McNemar、Holm 校正。

#### 3C 样本量与停止规则

1. 只用开发侧未用于调试的案例估计配对不一致率；
2. 以保守下界或最小可检测差异 10 个百分点估计样本量，目标 power 0.8、双侧 α=0.05；
3. 在打开留出标签前冻结 N、案例清单、主指标、主要比较和停止规则；
4. 不因中期结果追加样本；不因结果不显著换终点或删失败；
5. 正式报告同时给出所有执行样本、双方有效配对、改善/损害案例和成本。

#### 3D 成本与协调

- 报告预算档位上的质量—成本曲线；C0 是低成本起点，不能据 C4 优于 C0 声称纯协作增益；
- C4 vs C3 在相同预算上限下比较，同时报告实际调用、token、有效核查数和失败；
- 自适应若未优于固定调度，保留简单调度，不继续为复杂度找理由。
