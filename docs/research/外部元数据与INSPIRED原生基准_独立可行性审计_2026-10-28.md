# 外部元数据与 INSPIRED 原生基准：独立可行性审计

这轮工作不调用模型API、不使用任何密钥、不修改已冻结实验输入、case或summary。目的分别是补充可靠身份元数据和准备真正独立的会话数据集。所有原生ID与候选集合保持不变。

## 1. KG信息缺失的实证审查

已实现 native_kg_information_audit.py，产物 native_kg_information_audit_v1/audit.json。对旧8例800次候选与新32例3200次候选，比较已提供前3邻接和完整原生KG邻接。

前3常见实体并非主要为泛化国家节点，而是 Steven Spielberg、James Cameron、Judd Apatow、James Wan、Christopher Nolan 等姓名；完整邻接反而包含大量发行机构与国家。不能无证据声称“把前3改排序就能补齐电影类型”。

用当前Seeker原文中的固定类型词集合与邻接实体名字作词法重合：旧8前3和完整邻接均仅1/800次候选有匹配；新32前3为3/3200，完整邻接6/3200，只有3个候选因截断丢失该词法重合。它只是名字重合，不证明关系是genre，也不代表喜欢。该审查不读取标签。

因此暂不开发一个只重新排序匿名邻接的选择器。没有证据表明大量类型信息已在原KG里却被前三条截断隐藏。

## 2. DBpedia官方数据通道探针

核查了 [官方SPARQL文档](https://www.dbpedia.org/resources/sparql/) 与 [Linked Data文档](https://www.dbpedia.org/resources/linked-data/)。官方说明HTTP200也可能是部分结果，应保留X-SPARQL-MaxRows和X-SQL-State等响应头；公开端点不包括所有DBpedia数据集。

native_dbpedia_probe.py 按旧8第一例候选顺序选10部原生URI，不看实验标签，查询具名genre/director/starring/abstract。实际进行了批量10片和单片诊断，两者均在TLS阶段失败（SSLEOFError），没有HTTP响应，status_code=null。随后对同一第一部影片的官方Linked Data JSON单资源接口做一次独立诊断，也同样失败，现停止该网络方向。

所有请求、来源、时间、错误原文与原生URI分别存 native_dbpedia_metadata_probe_v1 和 native_dbpedia_linked_data_probe_v1。未关闭SSL验证、未重试循环、未发送用户对话、未访问模型API、未下载全目录。当前零条属性记录表示网络通道没有观测，不表示DBpedia数据库缺少这些电影属性。

## 3. 严格MovieLens genre元数据：可用但覆盖有限

native_external_genres.py 只读取本地movies.csv中的movieId/title/genres，绝不读取ratings、问卷或开发标签。外部movieId只用于元数据出处，输出目标始终是ReDial原生ID。

规则：原生DBpedia URI必须明确带(YEAR_film)或(YEAR)；双方只作Unicode/空格/大小写及MovieLens句末冠词格式的确定性规范化，规范title+year必须在原生集合和MovieLens两边唯一。不做模糊匹配、译名猜测、年份容差或从当前对话推断年份；无genre保持缺失。不删除任何原生物品或候选。

全原生6924项中：812项本来是裸数字占位、4536项URI不带符合规则的明确年份，均不链接。1576项具明确年份，1045项能唯一链接且有genre，即全集合15.09%；510项无精确外部记录、10项外部同名同年歧义、11项没有genre。旧8候选覆盖158/800=19.75%，新32覆盖602/3200=18.81%。

10片探针只链接3片：It(2017)为Horror；Scream(1996)为Comedy/Horror/Mystery/Thriller；Psycho(1960)为Crime/Horror。其余URI无明确年份不猜配。详细产物 native_external_genres_probe_v1/{probe10,audit}.json。

唯一精确title+year是可复算的身份证据，不等于人工核实；不同发行年份、译名与同名作品仍有残余风险。MovieLens类型体系是外部属性，不是当前用户偏好或ReDial目标标签。若后续采用，必须建立独立external-feature版本、全部方法同权限、保留缺失和全部候选，不能借覆盖筛选好看样本。四项针对性测试通过。

## 4. 裸数字原生item的训练侧标题补充

native_raw_titles.py 只访问原raw/train.jsonl的conversationId与movieMentions，且仅接受CID属于官方CRSLab train的交集6499条；不访问messages、问卷、rawtest或查询标签。空list的movieMentions跳过。

812个原生裸数字key直接是原始ReDial reference ID。按这个精确ID可唯一恢复606项标题、206项保持未知，零冲突。元数据只补全全局item名称，不把某个查询的未来提及或偏好作为预测证据，也没有把这些裸数字自动扩展到MovieLens genre链接。

产物 native_raw_title_metadata_v1/{native_placeholder_titles,audit}.json；两个访问边界与非模糊规范化测试通过。当前冻结NativeEvidence与正在运行输入没有热改。

## 6. INSPIRED数据质量边界

保留作者原生1815集合，不擅自清洗再称标准协议。发布链接中可见明确噪声：首条训练会话说Knives Out，movies却链接Knives Out(song)；原生集合还包含album、novel、character等非电影标题。

其KG虽有genre/director/starring等40种具名关系，仍不能直接当无误真值。例如源文件明确存在 Scream(1996 film) —genre→ Alternative rock。该反例已留档，未把这类跨数据集KG作为ReDial真实电影genre补充。

因此其标签适合测作者协议下的下一轮实体推荐预测，不等于电影事实、语义真实性或用户满意度。未来可另做预先规定的数据质量分层，但不得按模型成绩过滤或用修正后的集合冒充标准结果。

INSPIRED与ReDial都属于电影推荐，是独立会话数据集的外部检验，不应称已经证明跨领域泛化。当前test未读，可以在算法和对照冻结后用于未来真正的外部检验；不会依据这些valid结果替换掉不理想的ReDial研究结果。
