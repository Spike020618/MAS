## 二、原方法究竟要复现什么

1. 从真实训练交互构造正物品和流行度抽样负物品，负项排在前面。
2. 用户根据当前记忆和两个物品描述选择，输出理由。
3. 仅用训练反馈，更新用户记忆及物品描述；共享物品状态可把信息传给后续用户。
4. 保留跨交互的短期/长期记忆。不是每个请求重新创建角色，也不是冻结模型权重就等于没有学习。
5. 推断时使用训练后的记忆排序固定候选；区分basic、sequential和rag，不混为一项结果。
6. 按原始10候选协议评价NDCG，并记录重复运行差异。不能拿ReDial召回池Hit@5与原文NDCG直接比较。

## 四、真实数据核查

两子集均100用户，各500个训练目标、100个验证目标、100个测试目标。训练目标每用户5个；最早一项保留在历史字段，不可把700行误称为700条完整交互。包括历史在内的独立物品分别为dense269、sparse704。每用户末次测试历史与之前训练/验证连续，没有测试目标出现在自身历史的记录；所有交互和候选ID均有目录项。

该检查只证明提供的序列前缀一致；原始时间戳未随划分发布，不能进一步认证真实时间排序或采样过程。

每用户`.random`有100项。sparse的完整清单14行有重复，但按原代码形成的测试10候选没有重复；dense也没有。dense的10候选中24行含历史影片，sparse为0；原代码评分后会屏蔽历史，不静默重采样。这可能影响两子集难度，但本轮没有量化其性能影响，不拿它解释原文增益。

公开树清单只有Office相关旧pyc名称，没有Office固定数据路径。不得用自行抽取的Office样本冒充原论文固定样本；先以CDs复现，Office范围注明未获得。

## 五、做过的执行核查，不是效果实验

测试直接从已哈希源码抽取`calculate_loss`、`backward`函数体执行；不导入整个上游模块，不联网。模拟API响应仅检验分支，不代表模型行为。

- 首轮正确、第二轮正确：原函数仍执行两次forward。
- 首轮错误、第二轮正确：第二轮进入正确反馈分支。
- 首轮正确、第二轮错误：仍可进入第二轮错误反馈。
- 负项更新null：用户和正项记忆更新，负项不变。
- 负项更新True：原分支确实更新负项。
- 逐文件哈希与数据前缀核查通过。

共6项单元测试通过；它们确认行为和数据，不证明性能，也不是对上游实现正确性的背书。

执行：
```
python3 -m experiments.replications.agentcf.audit
python3 -m unittest experiments.tests.test_agentcf_replication_audit -v
```

## 六、后续复现验收规则

顺序固定，不以表现好坏挑规则。

1. **先完成安全运行壳及环境验收**：限定依赖版本；原始快照只读；适配补丁单独保存；有限重试、错误留档、费用与时间记录。原始数据和方法分支不在兼容修补中改变。
2. **原代码轨与论文协议轨明确分开**：默认先复现固定提交的实际行为；对温度、停止规则、负项更新的论文差异另设配置和差异清单。不得比较后只报告更好的版本。
3. **冻结并核验完整状态**：每一步保存用户/物品记忆、当前序列位置、训练输入哈希和反馈来源；重启后与不中断路径一致。测试目标不进入训练反思或记忆生成，独立评分器才读答案。
4. **零付费契约测试**：覆盖选对/选错、解析失败、空输出、重试、同物品跨用户传播、测试状态不变、排名重建、断点复跑。现有6项只覆盖一部分，不能跳过余下测试。
5. **才运行同后端小样本**：原AgentCF与无学习、仅用户更新、仅物品更新等对照共享模型、数据、候选、顺序与种子；计入训练成本。先验证实现和状态变化，再考虑多次完整运行。样本不按旧错题或喜欢的题型挑选。
6. **最后讨论增量**：复现没有成立前不加AEIC、奖励、均衡或新角色。即使AgentCF有效，也只支持该方法；新博弈贡献仍需独立设计和对照。

本地只有DeepSeek访问背景，尚未验证原文两模型可用性。若使用DeepSeek，报告标题和结果都写“AgentCF的DeepSeek后端替换复现”，同时记录请求别名和返回模型；不能宣称原论文数字被精确再现。本轮不启动付费调用。
