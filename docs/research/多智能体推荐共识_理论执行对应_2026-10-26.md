# 理论与执行对应检查

本轮未证明新的博弈定理。实现的有限矩阵求解器用于检查理论对象是否被准确表达，不作为推荐效果证据。

## 有限矩阵里实际证明什么

给定已声明的偏好状态h、可用集合s与损失矩阵A，推荐者采用集合分布p，对手采用状态分布q。两者分别最小化和最大化`qᵀAp`。

有限混合策略空间为单纯形，损失双线性，标准有限零和博弈有minimax值。程序分别解原/对偶线性规划，计算：

- 推荐者固定p时的最坏损失上界：`U=max_h(Ap)_h`；
- 对手固定q时推荐者最优响应给出的下界：`L=min_s(qᵀA)_s`；
- 对偶间隙：`U−L`；
- 当前双方单边改进空间：`qᵀAp−L`、`U−qᵀAp`。

数值间隙接近0只认证**这张矩阵中的混合策略**。如果列只是几个基线输出，不覆盖所有可行5项集合，证书就只属于这个受限游戏。采样一次集合按分布执行，与挑概率最大的集合不是同一策略。

合成矩阵`[[1,0],[0,1]]`的随机策略值为0.5，确定性最坏值为1；二者不能混称。机器单元证书位于`finite_game_unit_certificate.json`。

## 与推荐机制之间还缺什么

| 对象 | 当前状态 | 不能越过的边界 |
|---|---|---|
| Agent报告 | 有初始报告、两次审阅、最终排名与原始响应 | 报告角色不是不同自利效用主体 |
| 证据约束 | 检查来源存在与引用范围，记录更新 | 来源存在不证明推论正确；没有语义金标准 |
| 外部损失 | ReDial未来问卷正目标的Hit/Recall/NDCG | 不是完整偏好效用，不是当前用户满意度 |
| 偏好场景 | 三条分析路径可产生不同判断 | 不自动构成真实偏好的覆盖集合或校准后验 |
| 矩阵收益 | 软件可接收有限损失矩阵并求解 | 不用Agent自评分或词面新颖性冒充真实收益 |
| 均衡 | 标准有限矩阵数值验收可做 | 不宣称实际LLM行动构成自利博弈或Stackelberg |

因此先检验交互相对强参照的增量，再决定是否有必要引入集合决策博弈。即使交互有增量，仍需以独立数据建立状态可信度并固定损失；不能将交互效果与一个任意矩阵的定理拼接成“博弈机制有效”。

若开发结果未通过门槛，则本轮完成理论适用性核查，但**不进入实际推荐博弈层的效果声明**。这不是证明博弈普遍无效，而是拒绝在当前执行对象上使用不匹配的保证。

## 当前数据语义

ReDial参与者是完成对话任务的工作人员，不能把其跨会话身份自动解释为稳定的个人影视偏好。当前“历史适用性”只分析本次前缀内的自报偏好，不跨会话建立用户画像。参与者隔离主要控制信息共享和写作风格依赖，不认证持久真实用户身份。

当前资料仅有对话、片名、年份与类型。不足以客观核验复杂剧情、主题或人物关系；这些请求应保留未知，不将模型预训练记忆自称为可追溯资料。是否真的遵守这一点尚需独立语义审阅，不能由JSON结构测试代替。
