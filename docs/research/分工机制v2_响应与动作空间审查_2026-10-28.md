# 现有响应与动作空间审查

## 执行边界与结论

只读审查protocol_v2_frozen原始请求、回执、封存案例与输入，未改运行器、提示或原结果，未调用API。复核两批各37题generation_complete的逐例hash。复现命令：

```bash
.venv-native-benchmark/bin/python -m experiments.audits.audit_protocol_v2 --root experiments/results/protocol_v2_frozen --output experiments/results/protocol_v2_frozen_audit_v2.json
```

首次输出为experiments/results/protocol_v2_frozen_audit_v1.json。输出存在时拒绝覆盖。日志统计以事件为单位，跨方法相同请求可能复用，不能把事件计数当独立样本数。

第一、二步已完成；不满足启动第三步小批效果验证的条件。当前结果既没有博弈增益，也不足以用来判断有效协商机制的上限。下一轮不能原样重跑或扩大数量。

## 1. 30次拒绝的具体原因

学习估计下game的30次assigned_source_not_used：

- 30/30的指定资料确实在请求fetched_sources中，排除“资料根本没发送”。
- 30/30只引用此前已可见的旧资料，没有把指定资料写入E，也没有给指定资料建立support/refute边。
- 30/30修改字段与non_abstain_shape_only_not_a_recommendation里的示例完全相同（operation、value、a、b、evidence_ids、expected_version、preserve_ids）。
- 30/30主张逐字使用schema_example占位句“One relevant, testable premise; a hypothesis rather than a certified fact.”；原始HTTP内容也有这句，非事后normalize填充。
- 30/30 assigned_doubt没有指定source_id；其中只传doubt_id、target_claim_ids和question。系统文字没有明确要求非abstain必须引用本次指定source，只有程序后端grounded_patch施加此要求。

启发式game的66次同类拒绝，也全部只引用旧资料、主张全部是占位句，65次修改完全匹配示例。

判断：按现行合同，这些拒绝有依据，不是校验器漏认已合规引用；但发送给模型的合同不完整且示例偏向首条旧资料，存在可定位的提示设计问题。原始响应明显出现示例复用，不能把这些输出当作充分语义核查。不能仅凭日志断言修正示例就会有效，也不能替模型把旧source_id换成新source_id来“修复”历史结果。

示例：e2:rec:8602:5，game核查指定disjoint:012173add397e5bafa69bf51（The Matrix），响应修改却只引用disjoint:00b57c5481d02c5a62dbd6ea（The Witch），并原样复用占位主张和示例swap字段。这只能证明未遵守本次指定资料合同，不能证明建议swap正确。

因此本次分类是“30次操作合同拒绝均有依据；30次均存在示例复用与指派表达不足”，不是“30次语义错误”或“30次合理语义拒答”。没有独立语义标签，不虚构支持/反对判定。

## 2. 是否有真实的预算取舍

37/37题资料包只有3份；问答初始不读资料，剩3份，推荐初始读1份，剩2份。每题可核查3次，因此次数预算不强迫从候选中取舍。成本仍进入目标，可以影响是否放弃核查，不能说预算完全不起作用；但它不构成“多个高价值候选争夺有限核查名额”的检验。

两批各37/37题，game与central最终选中动作索引集合相同。启发式目标差仅浮点误差，学习估计目标差为0。执行顺序/Agent归属可能不同，不能等同为所有请求一致。

训练模型采用资料长度、可见数量、状态版本、候选数量、是否abstain等结构特征；没有疑点语义、资料与当前题相关性、Agent实际差异的估计。当前同质收益+少候选设置不足以检验信息分工优势。

不能从现有方法间最终答对差异，构造“换一个动作就会提高”的反事实：各组初始模型输出、顺序及状态可能不同；缺少同一状态下所有候选动作的可靠收益观测。

## 3. 资料准备存在的具体问题

37题只得到3种资料组合，总共6份独特资料；17道问答全部混入推荐训练统计。来源库的分区隔离检查通过，不等于检索相关性通过。

例如推荐训练邻居加权分数与“此前提及影片关联分数”来自另一条原始查询；把scope改成other_context并不能让该分数成为当前查询的检索分数。训练提及总数可作全局统计，但同一文本里的query-conditioned字段不能当静态全局材料迁移。这是准备器没有充分区分静态统计与条件统计的问题，代理应承担实现判断责任，不归因于用户数据质量或模型便宜。

37题的资料选择明显退化，现有数据不能证明它为每题提供了有意义的互补材料。不是建议另换研究主线，而是当前检索实现没有支撑主线所需的动作选择空间。

## 固定的最小整改范围（记录，尚未实施或启动新批）

1. 请求明确assigned_source_id、指定疑点与允许更新目标；移除能直接照抄的事实主张与具体答案/swap示例。保留必要字段合同。不强迫资料支持修改，不支持时允许abstain。原批不重标、不替换引用。
2. 恢复按任务种类与当前查询检索；静态背景可共享，条件分数须按当前查询重新计算或保留为显式历史案例，不能作为当前统计。对检索做相关性诊断，不使用答案标签选资料。
3. 检查自然候选是否多于可执行次数，且有重复/互补关系；不能只把上限调小来制造博弈胜利。真实资料仍没有取舍就不跑效果验证。
4. 上述合同/材料条件通过后，才按先前约定固定一次小批比较。不给博弈增加独占资料、模型能力或预算；不预设要击败同目标中央全局最优。

停止标准：未出现真实材料处理、指定疑点核查与有依据更新之前，不扩样本或宣称方法效果；修通后仍无增量，保留负结果并重新评估博弈是否适合作核心贡献。当前仅完成诊断，没有产生新有效性证据。
