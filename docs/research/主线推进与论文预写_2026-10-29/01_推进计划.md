# 多智能体博弈共识：推进计划与研究基本盘

版本：2026-10-29讨论稿。批准主线仍为“预算约束下基于证据贡献博弈的多智能体共识机制研究”。本文组织后续工作，不改正在运行的同状态诊断，不启动新API，不替换历史结果。

## 1. 统一研究问题

多个智能体持有不同材料与初始解释时，如何针对会影响最终决策的疑点，在有限资源下选择核查、交流依据并修订共同状态，形成更可靠的共同答案或排序？

“理解”以识别主张条件、来源适用范围和冲突，并作出正确修订来操作化，不以解释长度或答案一致率代替。“共识”指有可追溯依据的共同决策；允许保留未解决分歧。证据更新与预算协调属于一个完整机制，不分拆成两个研究点。

## 2. 拟议贡献及必须获得的证据

|贡献候选|具体内容|与已有工作的区别需要落到哪里|成立所需实验|
|---|---|---|---|
|C1：面向共同决策的证据状态与受限修订|把具体主张、原文依据、适用范围、未决分歧和版本化补丁连接起来|不以新字段为创新；研究纠错如何落实到共享状态，并保留原本正确的信息|E1核查与修订质量；E4去掉受限更新的单因素对照|
|C2：状态相关的核查贡献估计与预算协调|估计不同Agent处理某个疑点/资料组合的预计任务收益，随已接受的修订重新计算|区别于仅按文档相关性筛选；必须测实际核查收益、必要的资料组合和状态变化|E0动作诊断；E2选择质量；E4去掉组合信息/状态更新|
|C3：证据贡献博弈驱动的共识形成|用明确行动、公共预算和边际贡献组织核查，再通过有效局部修订更新共同决策|不是角色扮演或仅证明收敛；需显示协调相对简单策略的实际价值|E3完整方法；E5预算与干扰；同目标中央、同选择能力单Agent均比较|

三项是一个方法的组成部分。当前只是贡献候选，不写“首次”或“显著领先”。已有研究覆盖讨论/投票分解和组合资料价值；本项目拟检验的差异是主张级核查、状态反馈和预算协调如何共同作用。需实验建立，不能靠组合命名成立。

## 3. 方法的固定骨架

互补材料处理 → 登记主张和决策相关疑点 → 生成可执行核查动作 → 估计状态相关贡献 → 在预算内协调选择 → 核查并提交有依据的局部补丁 → 更新公共状态 → 重新评估未解决疑点 → 共同读出。

动作明确为a=(Agent、目标主张、资料集合、允许修改范围)。资料集合可为单份，也可为有证据支持的两份联合核查；联合核查允许单Agent完成，不能为了多Agent获胜强制拆开。集合价值v2已接通组合核查、四分支匹配训练、集合目标分配与状态重规划，统一入口见05_运行说明.md。

预算至少分开记录模型调用数、读取资料数、实际Token与货币费用。两份资料的一次联合核查与两次单份核查成本不同；所有方法获得同样的联合行动权限。默认v3的货币上限并不紧，不能以其结果宣称紧货币预算优势。

贡献估计保留单动作及联合动作价值，不把单项收益机械相加。联合资料的正负作用须从训练/开发证据识别；没有可信交互信号时，组合项设为0，不能为了博弈需要虚构互补。

预算博弈的定义与中央优化共享同一估计目标和可行域。固定状态下的求解证书只证明该代理游戏的稳定性；状态更新后重新构造游戏，不能把不同状态的势值当同一个全局势函数。全程终止由有限调用预算和合法状态更新约束保证。

## 4. 六种主要比较做法

|做法|执行方式|主要回答的问题|
|---|---|---|
|一个Agent使用同样贡献估计与反馈进行核查|同样资料权限、初始投入和联合动作权限，保留完整自身记忆；采用与协作组相同目标的强选择策略|增加Agent组织是否提供独立收益？不能继续用弱固定选材单体替代|
|多个Agent独立处理后汇总|初始材料分工；追加预算相同，各自处理，最终固定读出|完整协作流程比独立计算多得到什么？此比较本身不单独识别交流作用|
|按固定规则交流与核查|共享初始信息，采用与收益无关的固定合法指派|动态选择是否优于固定投入？|
|直接按预计贡献选择核查|与完整方法共享估计器和动作集合，直接排序或预算内贪心|复杂协调是否超出简单选择？|
|中央统一优化|同估计目标、同动作、同证据权限和预算，枚举或精确求解|博弈相对集中分配的代理差与实际差是多少？|
|证据贡献博弈与局部修订|按估计边际贡献协调，执行有依据修订，随公共状态变化重评|研究方法整体表现及协调作用|

单Agent可使用强选择器，也可模拟多个视角。若与协作方法执行功能等价的程序，应接受结果接近；不能通过限制单体记忆、资料或操作制造必要性。中央代理目标最优值是参照，不预设博弈应击败它。

## 6. 各实验的目标与预期模式

### E0：是否存在可以利用的核查价值

使用当前8题面板，不变更。希望观察到部分动作的重复收益差异，以及可能的联合价值；这是待检验假设。如果差异主要来自无效输出、空集重新思考或重复噪声，就先修识别条件，不将其当协调信号。

### E1：是否能有依据地修正目标，并保留其他信息

受控程序用例覆盖支持/反驳/不足、过期版本、引用越权、局部交换和无关位置保留。自然语言核验采用公开标签作为独立评价，不要求用户新做人工标注。FEVER提供Supported/Refuted/NotEnoughInfo及部分证据标注，可作为核查子任务基础：[原始论文](https://aclanthology.org/N18-1074/)。

当前实现锁定原始Climate-FEVER的180个claim，每个claim按hash取一条人工标注证据，不另训练核验器。该证据关系子任务与原FEVER claim级评价区分。受控证据给定与真实检索分开：给定标注证据仅用于检验核查能力，不冒充部署检索效果。NotEnoughInfo必须相对于指定证据环境解释，不能将任意截断后缺证据直接等同原生NEI。运行器看不到标签；评分器在封存后读取。

指标：三态宏F1与混淆矩阵、错误目标纠正率、原本正确目标误改率、未解决比例、保留信息的正确率、引用检查有效率。生成式推荐理由没有独立标签时不报告自然语言真实性百分比。

### E2：能否事先选中较有价值的动作

在与实际执行相同的核查格式上采集贡献训练数据，单份与联合动作都有覆盖，记录失败的真实策略结果。训练/校准/评价按原始QA题或会话分组，面板已看过的8题只能作开发材料，不再当正式验证。

比较均匀合法选择、检索分数、直接预计贡献、固定规则与同状态事后诊断。主指标为实际执行净收益、相对简单选择的配对差、选择后的损害与成本。标签oracle只给固定观察池的参考范围，不作可部署基线。还应报告预测误差与排序选择质量，两者不互相替代。

### E3：完整共识机制是否产生可归因收益

StrategyQA回答质量为主要可判定任务，ReDial为推荐迁移应用。两个任务单列，不相互借分数。每方法同信息访问、同预算上限、同模型版本与任务；实际tokens与费用报告。主要比较预先定为完整方法对独立汇总；同选择器单Agent、直接选择与中央用于识别收益来源。

QA报告正确率及配对纠正/损害；推荐报告Recall@10、NDCG@10、候选覆盖，已有提及与新影片诊断另列，不能当满意度。失败保留在主分母。按QA原题或推荐原会话聚类配对重采样。主比较与次要比较预先指定，多重比较、模型重复和开发暴露完整说明。

### E4：哪个环节发挥作用

采用五个单因素消融：关闭二阶交互、关闭集合去重、关闭状态重规划、禁用联合资料行动、允许自由重写。每项维持其他模块及预算一致，必要时采用固定动作日程条件实验，不把动作选择变化和消息变化混说。

自由重写/语义判定较弱的版本只是明确标记的实验消融，不进入实际服务默认流程。保留正确内容通过有标签子任务评价；在推荐中排序位置保持仅是结构指标，不代替正确性。

### E5：预算与干扰下是否仍有价值

追加调用上限K∈{0,1,2,3}，主配置K=2；资料数、tokens与费用同时报告。缺失、精确冗余、低相关背景三种资料条件沿用已预写的干扰定义，不根据结果重选扰动。默认不穷举所有K×干扰×模型，预算曲线在基准环境，干扰在主预算。

希望完整方法的质量—成本折衷优于固定投入与直接排序，但需实测。若仅省钱却低于不核查强排序器，不称有效提升；若与中央接近，只能支持近似/组织能力，不能称超越同目标全局最优。

### E6：是否依赖单一模型

先在固定主模型完成主实验，再在一个可用的第二模型上运行预定子集。不先假定哪个更强，也不要求用户追加购买。共享数据、动作和预算合同，记录真实返回模型及解析失败。跨模型方向不一致需报告；单模型正结果不能写成通用有效。
