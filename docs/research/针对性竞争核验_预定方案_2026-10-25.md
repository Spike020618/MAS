# 针对性竞争核验：采集前锁定方案

## 要检验的改变

把固定答案后处理改为提交论证、具体挑战、适应性回应与证据核验。证明者希望固定候选被接受；挑战者定位一个决定性问题并发出真实原文查询；证明者看到挑战后回应，核验者再判断。这里实现的是角色化交互，不把固定 API 模型说成天然自利主体，也不宣称一次回应就是最优响应、完成训练或求得均衡。

本轮只检验协议是否有价值，不设计支付、不证明 Stackelberg、不以旧效果背书。所有 Prompt、窗口、解析与预算在模型调用前冻结。

## 数据和标签

6篇新 QuALITY 官方 dev 原文，与上一轮20篇的 article_id 和全文哈希均无重叠；按输入哈希选择、每篇一道题。历史请求精确题干排除，不保证语义/预训练未见。不筛难题或已知错题。

每题四个原生候选全部纳入，共24项候选主张，包含一个官方最佳答案和三个非最佳答案。候选角色分配不读标签；证明者只知道被指定的候选，不知道它是否为最佳答案。标签与人类验证字段不进入任何请求。

判断对象是“该候选是否为原问题的最佳答案”，不是整个论证在哲学或形式意义上的真值。原始材料可以被模型读取，但金标准解释、检查标签与人工理由不能作为工具证据。

## 行动与同预算对照

先同模型全文直接问答一次，作为便宜的强参照。随后对每个候选：

1. author：看全文，提交支持固定候选的最强论证与原文引用；不改候选、不编造来源，允许诚实说明局限。
2. ordinary0/1/2：同一份 author 论证，三个顺序普通全文核查。后续可见此前审阅，不接收挑战者额外信息。
3. restatement：在挑战出现前，证明者只对自己的原始论证作普通重述。
4. challenge：不看普通核查结论、不看全文，根据论证提出一个具体问题与查询。
5. 工具访问：用查询对真实原文词面检索，保存最多6个220词窗口、字符位置、原文哈希。无效挑战回退题干和所有选项的固定查询，另记失败。
6. reply：证明者看全文及具体挑战，回应这个问题，但保持候选不变。
7. nonadaptive：核验者看原论证、挑战和此前普通重述，以及相同查询窗口。
8. interactive：核验者看原论证、挑战及适应性回应，以及同一查询窗口。

每候选9次物理调用：author、ordinary0、ordinary1、ordinary2、restatement、challenge、reply、nonadaptive、interactive。每文档37次（含全文原生问答），总上限222次。

各最终方法包含依赖的 author 成本：ordinary2 为 author+三次普通核查；nonadaptive 为 author+重述+挑战+最终核验；interactive 为 author+挑战+回应+最终核验，均4次。普通单核查和原生问答成本也单列。相同调用次数不等于相同 Token、信息或实际计算。

ordinary 核验可见全文，是强基线；两种交互最终核验只见查询窗口，信息权限不相同，应明确披露，不声称单一因素因果归因。nonadaptive 与 interactive 的最终输入结构和窗口相同，区别为回应是否针对实际挑战。

## 模型与记录

固定 DeepSeek 返回模型 deepseek-flash、既有 fingerprint、非思考、temperature=0.2，各阶段输出上限1000。最多三篇并发，HTTP/版本/未知传输失败停止后续调用；在途请求可能完成，不自动重试、不调用 Qwen。

严格注册候选，模型不能修改其身份；引用只检查来源字面保真，不把匹配结果当正确性奖励，且不给后续模型转发机器匹配提示。完整 JSON 所需字段可带无害元数据，不能靠格式键制造增益。无效或弃答保留并在核验风险中记错，不用解析恢复追加模型调用。

## 指标和停止条件

主指标为按问题宏平均的(误收率+误拒率)/2；每题一个正类、三个负类，避免一律拒绝获伪优势。总24候选不是24独立问题，独立来源组只有6。

同时报告明确误收、误拒、弃答/非法、唯一接受候选时的问答正确数/弃答、Token、调用、HTTP耗时。多候选都接受或存在未决项时，严格唯一接受读出弃答，不能事后挑正确者。

主比较 interactive vs ordinary2，nonadaptive 为必要的针对性回应消融；原生全文问答与单核查不能省略。仅六问题的工程开发屏，不凭小数差宣布显著、普遍有效或博弈必要。

若未超普通核查或非适应性回应，停止原样扩样，不调奖励或加强攻击直到出现好看的混合解。若出现一致正向，还需锁定协议在更多新文档独立验证，之后再考虑学习与均衡；本轮不自动进入下一阶段。
