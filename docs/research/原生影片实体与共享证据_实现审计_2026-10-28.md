# 原生影片实体与共享证据：实现审计

已实现 `experiments/paired_deliberation/native_entity_evidence.py`，为原生 ReDial 的任意训练/验证前缀提供实体展开、训练邻居、训练关联和可引用KG邻接材料。该组件不调用模型、不读取查询标签、不读取测试文件或旧自定义reserved数据，不使用MovieLens映射或问卷。

## 已产出

`experiments/results/native_entity_evidence_v1/fixed32.inputs.json` 保存32个既有开发前缀的完整共享证据；`audit.json` 保存原始输入、代码与官方数据文件SHA256，以及映射和隔离指标。

- 20,724个作者协议训练推荐前缀拟合文本邻居。
- 从官方训练逐句标注得到4,908个无歧义原始影片编号至DBpedia实体链接，训练链接冲突为零。
- 32个查询前缀共105次影片编号提及，101次可靠展开，覆盖96.19%；4个前缀各余1次未解决编号，保留原文而未猜配。
- 同一原始conversation的训练邻居排除，当前产物中此类邻居为零。
- 八项针对性测试通过，包括歧义、不完整标注、未来响应载荷访问陷阱、来源角色隔离。

## 身份映射规则

只用 CRSLab 官方训练utterance的原始 `text` 与 `movies` 约束；先收集“唯一原始编号—唯一DBpedia影片”身份关系，再用已知关系消去同句多个提及中的唯一剩余一对。仅当独立编号数和原生影片实体数一致，才接受后一种唯一剩余推断。若一个编号出现冲突，保持未解决。

查询时允许使用当前可见前缀的原生实体注解作同样的唯一消歧。这是作者推荐模型的输入侧实体材料，不读取当前推荐者响应的文本、影片或实体。`visible_prefix` 在当前响应开始时立即停止；测试使用一个一旦访问未来text/movies就抛错的对象验证该边界。

原始 `@编号` 展开为片名、原生KG影片ID，并保留原始编号便于追溯。没有模糊片名匹配，没有按实验标签插入影片。发布数据自身的实体标注错误无法靠该映射规则纠正，因此不称人为核实的电影身份真值。

当前未解决：204794、81792（两处）、159810。它们的可见原句没有相应原生影片注解，或原句多个原始编号只有部分已链接实体；不能据剩余一个实体强行指派给未知编号。

## 同权限证据接口

`builder = NativeEvidence()` 拟合一次；`builder.augment(row, history_limit=3, kg_limit=6)` 接受 `{id,text,candidates:[{movie_id,title}]}`。`id` 使用原生 `conversation:merged_turn`；输入text必须与作者发布的该可见前缀逐字一致，否则拒绝。

返回：

- `text` / `canonical_text`：已展开前缀。
- `original_text`、`candidates`：保留原输入与候选顺序。
- `sources`：source_id键值字典，每张卡绑定kind、origin_case_id、原文、allowed_use、原角色和影片ID。没有模型自由生成身份或授权字段。
- `candidate_evidence[movie_id]`：训练邻居加权分、历史提及至下一轮目标的关联分、训练推荐者下一轮提及频数、KG邻接信息。
- `training_neighbors`：至多三个当前文本近邻的其他训练对话前缀与其观察到的下一轮推荐影片；不是当前用户的喜好。
- `mapping_audit`：每例编号覆盖、未解决/冲突记录与训练隔离标志。

训练邻居使用词/二元词TF-IDF与前50正相似度的训练前缀；多目标训练响应按目标数归一后投票。历史关联按训练前缀中已提及影片至下一轮推荐者提及的目标进行计数与条件归一。两个统计都不能解释成用户喜欢概率。

来源ID规则：`dialogue:N`、`history:conversation:turn`、`train-score:MID`、`kg:MID`。用户原话卡为current_expression；当前推荐者原话为dialogue_context；历史邻居与统计为prediction_basis；原生KG为catalog_attribute。只有当前Seeker原文卡有当前表达身份权限。所有卡的semantic_entailment_certified均为false。

旧 `scoped_evidence.cards()` 不识别 knowledge_graph 的目录类型，不应再对这些已绑定卡重分通道；直接使用原卡中的allowed_use。

## KG和输入长度限制

官方发布包包含原生数字relation_id和邻接实体，但没有关系名词典。组件明确提供原始数字关系及邻接实体名字，不推断演员、导演或类型语义。不得把“69→某人”写成已认证的演员关系。

完整审计对象每例约202–218KB（kg_limit=6），不能整包直接发送到64KB请求上限。模型入口应发送紧凑表：每候选统计一行、KG只保留必要的若干 `[relation_id,entity_name]`，来源ID绑定完整原卡。各方法的信息访问权限应一致；记录实际提供的证据子集与token预算。完整材料仍保留供回放。

主模块已在2026-10-28交付父runner冻结；该审计只说明材料和身份隔离，不声称推荐指标已提升。后续真实API结果由主实验记录。

## 主实验入口独立审查

审查了 native_evidence_optimization.py、native_optimization_runtime.py 与 native_candidate_challenge.py。主入口把统计/KG压缩成列名加每片一行，初始Agent按KG与历史子集分工，单模型和追加独立调用访问完整材料并集，中央与博弈挑战共用目标、成本和来源权限。这符合本轮同信息权限及六调用上限的探索设计。

确认的来源边界问题：挑战请求只提供候选对的KG/统计卡，但最初调用更新器曾传完整来源表。这可能使未实际提供给模型的source_id通过验证。已向主代理指出；主代理确认API启动快照已改为仅传请求内实际offered来源，因此未将该问题留在启动版。不能只检查来源在数据库中存在，还必须检查其在本次请求中可访问。

回退策略：无效排序保留相同检索或自身上一状态，无效挑战保留公共排序。主结果应报告全部样本及 all_calls_valid；该主策略与前批“任一路径失败整例计零”不同，不可将跨批差分全部解释为算法收益。

需要保留的两个动作空间限制：

1. build_targets保证供选择的疑点列表含初始三个Agent共同遗漏的新候选，但中央/博弈分配不保证真的选择它。必须报告 new_to_union_selected 和新候选实际进入Top10的数量。若该过程计数为零，不能声称检验了共同盲区恢复。
2. protected_prefix=3固定保留前三名，因此挑战分支不能提高Top1；默认六个目标实际只挑战原公共排序第5–10名，原第4名也未进入六个目标。当前主指标@10可以探索，但不能把@1无变化解释为模型完全没有改善能力，也不能把该原型称为全排序协商。

额外适用边界：组件可以重建训练前缀用于材料诊断，但全局统计和向量器本来就用全部训练数据拟合。只有发布valid前缀可作为当前效果评估；不要把训练前缀当独立验证，因为全局训练频数/关联仍含其训练对话。当前32例和主代理拟用的新验证样本均来自valid，不受此问题影响。
