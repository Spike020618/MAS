# 统一E1：状态落实与实现边界独立审计

对象：`experiments/results/unified_e1_v3/`冻结源码和最终状态。审计不修改package、输入、原始响应或旧分数，不调用API，不读取任务答案标签。静态检查先于全局封存；完整状态回放只在`generation_complete.json`存在并核验后执行。

## 1. 已实现内容及允许表述

P0最小任务协议已支持原生yes/no QA与原生推荐候选/排序，任务ID、选项、资料目录、可见来源及预算均进入状态。整次任务方法级预算包含初始调用和复查调用；共享初始请求也按逻辑部署成本计入各方法。物理缓存费用另计，不能与方法部署费用混淆。当前QA只验StrategyQA二元答案适配，不能声称原生MMLU多选已接线。

P1已支持AEIC的原子主张、来源ID、support/refute/unclear边、版本patch与显式弃权。证据只能来自已实际展开且权限允许的来源。只存在source ID不等于语义支持；来源真假、事实真假、预测价值是不同问题。所有已注册主张初始仍为unverified。

P2最小真实动作已能从本地历史资料目录展开此前未见的材料，保存before/after可见来源；重复展开记为reuse且new_sources=0。此批实际获取是**已有本地快照的材料展开**，不能称实时网络检索、独立新事实确认或外部工具核验完成。

已具备初始生成→来源提议→分配→真实材料展开→模型审阅→局部patch→下一次审阅的在线状态链；不同方法共享同一资料权限。该E1用于工程接线和机制可执行性，不是最终算法效果主实验。

## 2. accepted patch是否真正影响最终决策

冻结runner在每次有效审阅后调用register_report，再调用apply_patch，并明确执行`state=result['state']`。方法结束直接保存`decision=state['decision']`。因此不存在“accepted但仍把旧decision送去评分”的静态脱节。

QA允许set_answer；推荐允许swap_candidate，正常运行拒绝replace_ranking整表重写。每次swap只改变两个明确ID的位置，其他位置保持；sourcecatalog及fetched来源内容通过hash/一致性检查。旧expected_version、未fetch来源、越界候选、非法用途不能执行patch。

当前runner不允许update_claim进入审阅执行集合。核心确实有update_claim操作，但它仅改主张状态，不包含从修改主张推导新答案/排名的自动读出；因此不能宣称E1已验证“改正某条推断即自动完成最终决策更新”。本批决策变化来自显式set_answer/swap_candidate。

拒绝patch时apply_patch保持其输入状态原样；此前成功的register_report可能已经增加unverified主张。必须区分“报告登记”和“修改决策”两个事件，不把patch拒绝解释为整次审阅完全没有状态变化。

## 3. 必须披露的实现边界

1. **语义疑点未完全实现。** 当前候选来自多个未见来源，doubt描述为同一条通用句。不是具体claim、可证伪前提、遗漏候选和反例的多疑点生成器。可称多来源提议接线，不称最终多疑点质量已验证。
2. **P3尚未实现。** 来源分数由metadata关键词重叠、模型提出的source ID及来源kind加分构成，未拟合真实纠错、误改或来源互补价值；同质player有相同gain表。
3. **五条件不一定产生不同资源分配。** fixed也从排序后的来源候选取前3；中央和博弈在同质加性覆盖场景可能选同一集合。必须看实际动作与最终状态，不能将同分解释为博弈已超过固定或中央。
4. **swap方向目前只在prompt约束。** core允许既有rank内任意两个ID交换，未硬要求a在Top10且b在外；实际是否出现需要封存后审计。非目标位置保持仍可独立核查。下一版本应将目标/范围约束显式写入任务patch验证，而不是依赖提示。
5. **语义支持仅被模型声明。** linked_patch检查patch证据属于E，且至少有support/refute边，不验证这些边在自然语言上正确，也不保证边指向被修改决策的全部前提。不能据此称已认证真实性。
6. **资金未知不计零。** BudgetLedger对未知结果保留预留calls/tokens/CNY上界，实际回执另作物理费用审计。若共享初始调用缺失event.usage，方法逻辑账本可能保守保留上界，即使原始回执已有用量；不得把保守上界当平台实际收费。
7. **同上限不等于相同实际资源。** independent只使用3个共享初始调用，其他方法另加来源复查；single顺序初始调用也与共享多Agent初始不同。E1可检验接线，但若未来声称交流优于额外独立采样，还需让独立方法在相近实际调用/Token费用下追加采样，不能只凭cap=12相同完成算力归因。
8. **多轮和可用预算有限。** E1按预先选中的最多3来源顺序复查；当前一轮提议/分配，不是在每次新证据后重新生成动作集和贡献博弈。可以称在线顺序更新，不称最终两轮自适应资源博弈已完成。

## 4. 独立回放与完成后结果

脚本：`experiments/audit_unified_e1_state.py`。该脚本首先核对live/source_snapshot与plan源码SHA，再检查全局输出seal；不读取答案文件。根据初始实际报告重建每个方法状态，重放来源展开和报告登记、逐个patch验证决策、版本、非目标排序位置和最终readout。另查未知费用保留及任务预算边界。

```bash
.venv-native-benchmark/bin/python -m experiments.audit_unified_e1_state --output experiments/results/unified_e1_v3
```

产物：`independent_state_replay_audit.json`。全局采集尚未封存时不得执行完整审计或提前读取任务标签。以下结果在24任务全部封存后取得，未读任何任务答案标签。

实际完成：120个方法状态全部精确回放；232条逻辑审阅事件中14个accepted patch均落实到state及最终decision，211个拒绝/弃权、7条无效未进入patch。没有accepted回放失败，没有实际swap方向违规，非目标排名位置没有变化。5条方法账本unknown记录均保留正费用上界，其中同一共享初始未知请求在四个方法逻辑账本各占0.09元，另一个single未知占0.006102元；它们不是5个不同物理请求，也不是平台实际账单。

另做封存状态反事实门控探针：120/120错误版本patch被拒绝且原状态不变；72/72有未展开来源的状态拒绝用该来源执行patch。结果为`independent_state_gate_probes.sorted.json`，复算命令：

```bash
.venv-native-benchmark/bin/python -m experiments.audit_unified_e1_gate_probes --output experiments/results/unified_e1_v3
```

上述检查证明E1执行状态和控制门控按合同落实，不证明14次修改正确，也不证明自然语言来源真的支持了修改。纠正/损害需使用另外的封存后任务评分；本审计未读取这些标签。

## 5. 下一阶段优先改动（不热修本批）

先用E1证明动作—证据—patch—readout链条真实落实，然后新版本实现具体claim/候选的多个疑点、动作级收益与风险校准、来源去重/共享外部性，并按每轮新state重新分配。QA与推荐共用核心，但各自读出应明确关联被修订主张；不要靠新增字段、更多提示或把同质gain表称为能力分工完成这些要求。
