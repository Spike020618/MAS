# 多智能体推荐：补充定位

本轮为文献核查，没有新实验或方法有效性结论。前一份集合优化调研不是完整的多智能体相关工作，也不意味着用户已同意将研究替换为纯重排优化。

## 直接相关文献

1. **MACRec，SIGIR 2024演示论文。** Manager、用户/影片分析、检索、反思与任务解释等角色协作完成推荐。适合继承角色接口和工程工作流，但框架演示不是多智能体增量或严格均衡的证明。论文初版HTML含未清理模板信息，年份与类型以正式出版和官方代码为准。
   [论文](https://arxiv.org/abs/2402.15235)；[正式出版](https://doi.org/10.1145/3626772.3657669)；[作者代码](https://github.com/BLyndon/mac-rec)。不要与AAAI 2026同名的对比学习MACRec混淆。

2. **AgentCF，WWW 2024。** 用户与物品分别建Agent，依据模拟决定与真实交互的差异，协同更新记忆；底层语言模型固定。可借鉴训练反馈驱动的多方偏好建模，而非只改角色提示词。它不是独立收益主体的均衡机制；训练时更新记忆也不同于测试时读取标签。
   [作者论文](https://arxiv.org/abs/2310.09233)。

3. **EyeCRS，WWW 2026。** Not All Information Brings Benefits: Personalization-Driven Agent Debate for Conversational Recommendation。正反Agent判断历史对话是否对当前个性化有帮助，后续还有参数化注入模块。辩论针对具体历史信息的取舍，而非无条件辩论所有答案。本轮取得正式摘要，尚未全文复核其数据、消融与预算公平性；不能把完整方法效果全部归给辩论，也不能称它是固定API零训练方案。
   [正式论文摘要](https://doi.org/10.1145/3774904.3792152)。

4. **Recommendation as a Communication Game，EMNLP-IJCNLP 2019。** 使用GoRecDial，将专家与寻求推荐者的对话建成有共同目标的合作游戏，以bot-play学习对话策略，并进行人类参与评价。说明多方交互应改变可观测决策；合作游戏不等于已经证明某个Nash均衡，也不是多个专家内部达成共识。
   [论文与数据说明](https://aclanthology.org/D19-1203/)。

5. **Emergent Alignment via Competition，ICML 2026。** 研究具有不同效用的AI建议者与用户的策略交互，采用多领导者Stackelberg模型；其部分保证依赖用户效用接近Agent效用凸包等条件。MovieLens相关实验检验效用表示的组合潜力；均衡结果另有策略模拟，不能合并宣称真实电影Agent在线交互已达到理论均衡。
   [正式页面](https://proceedings.mlr.press/v306/collina26a.html)；[已查方法与实验结构的预印本](https://arxiv.org/html/2509.15090v2)。当前项目没有自动满足其信息结构、效用或策略最优性条件。

## 对当前方向的修正

保留一个问题：**有互补但不完备的用户偏好与影片证据时，多Agent怎样形成更符合请求的推荐决定？**

这里至少有三种不同对象，不能混同：

- 分工协作：共同目标，不同工具或信息；优先测信息生产与协作增量。
- 推断审议：竞争的是对同一用户偏好的解释，重点是证据支持与更新；不同解释不是不同真实利益主体。
- 战略竞争：具有不同效用、可选择策略和明确交互规则；才讨论与实际机制匹配的均衡。

集合优化作为输出决策层和非交互强基线，不替代多智能体研究主体。AEIC若保留，先作为可审计接口，不预设四字段有独立性能价值。

## 借鉴后的必要对照

先验证信息互补，再验证交互：单Agent获得全部同源证据；多Agent独立分析加简单聚合；同信息下的证据交换协议；集合优化强基线。分别披露总调用、Token和耗时，预算上限对齐。不得人为遮蔽单Agent本可访问的信息来制造协作必要性。

暂不以本调研作为启动付费辩论的依据。下一步应全文核查最贴近任务的方法、其代码和消融，明确继承模块与拟优化模块后，再冻结小验证；不能“看到有多Agent论文，就给当前重排器加角色和均衡名称”。
