# 先分资料再采集

新增`experiments/prepare_disjoint_acquisition.py`，只准备，不调用模型或读取labels。首先按原始问答/推荐对话hash确定fit/calibration/diagnostic，再将真实资料按正文身份与文档URL连通组件分入唯一资料库。任务只能检索本partition资料。词重合仅用title/kind，不看正文决定相关性，不伪称检索资料充分支持问题。

默认document模式：相同URL不同段落也不能跨组；content模式仅正文精确隔离，是较弱协议，须显式选择。不足以形成三个资料库则输出split诊断并拒绝，不偷偷退回随机题组。保留所有原任务，重绑定source权限只允许prediction_basis，保留origin_scope，不能将其他问题的材料升级为当前用户事实。

```bash
.venv-native-benchmark/bin/python -m experiments.prepare_disjoint_acquisition \
 --inputs experiments/results/e2_action_acquisition_160_live_v1/inputs.json \
 --output experiments/results/e2_disjoint_materials_v1
```

输出tasks.json和split_commitment.json。必须重新实际采集：旧160回执对应旧资料，不能用新任务库套旧响应冒称跨来源训练。collector需要接受新tasks输入并保留这个预分配，而不是训练后重新连通随机分割。具体collector入口由集成脚本提供。

真实库可能稀疏或不相关，保留并报告，不为凑覆盖按gold补答案。URL别名、镜像及未提供docID可能仍是同文档，精确来源隔离不是语义独立证明，正式采集应保留更强的原文档谱系。

3项测试通过：不修改原任务、正文/URL无跨组共享、同原题固定分组、同URL连通导致库不足时拒绝。没有执行付费实验。
