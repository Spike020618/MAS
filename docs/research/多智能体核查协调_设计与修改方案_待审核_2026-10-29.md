# 多智能体核查协调：设计与具体修改方案

日期：2026-10-29。状态：待用户审核，未授权实施。

本次只新增本文档。不修改实验程序、运行配置、冻结数据、论文或中期报告；不启动采集，不调用模型，不替换 ACTIVE_RESEARCH_PLAN。下列目录、接口、预算与门槛均为拟议设计，不代表已经实现或验证。

## 1. 目标及不变项

唯一研究问题：具有不同局部证据状态的成员，如何通过有依据的核查分工和共识更新，在有限资源下改善共同决策？

博弈的对象是成员核查行动之间的重复、互补及资源竞争，而不是模型是否愿意服从奖励提示。玩家是可执行的程序化决策主体；基础LLM负责生成核查结果，不假定它天然理性、自利或独立付费。

保留“一个共识方法＋一个系统实现”的毕业设计结构。本轮只研究方法，不改影视系统，不改开题题目，不以已有排序收益替代新机制效果。AEIC可以作为报告的组织方式，但不强制四字段，也不以字段完整性结算质量。

必须区分两种验收：

1. 有效性：在同模型、同资料权限及同资源约束下，完整方法改善真实任务结果。
2. 协调归因：在相同估计器、核查器、更新器下，协调规则相对强非博弈规则仍有可测增量。

只有第一项，不能宣布博弈独立有效。均衡证书也不能替代任何一项。

## 3. 场景与信息权限

### 3.1 第一验证域

先使用HotpotQA原生多文档任务检验方法，不继续只在二分类关系与两包资料上迭代。题目包括自然问题与原始候选段落；保持资料池完整，不按答案、支持句或实验收益筛题。原生答案和支持事实用于训练监督、封存后评分，不进入测试提示、资料分工和动作生成。

必须先核对项目历史暴露清单。已经用于选方法的458条yes/no及其他历史题不能再称未接触确认集。新划分来自核实可用的数据分区；若无法找到干净分区，显式标记开发暴露，不伪称独立测试。按题ID、规范化问题及必要的近重复组去重；共享百科文档不自动视作题目标签泄漏，但须报告。

第二域再接原生ReDial，检验候选比较与局部排名修订。本轮不同时开发两个域的全部机制，以免把适配器问题与协调问题混在一起。

### 3.2 成员差异

默认三个成员使用同一模型版本、相同核查提示和采样设置。差异先仅来自按无标签规则分配的初始阅读以及后续真实读取历史；采用平衡分配并轮换成员编号，避免ID即能力的伪相关。

原始资料池对所有方法具有相同访问权。成员尚未读取，不等于中心永远不能读取。基础公平比较允许中央和单Agent获取相同信息，并计入读取与通信成本；不能人为禁止强基线合并资料。额外的局部通信约束只作为明确标注的部署条件，不冒充一般场景。

## 4. 在线执行设计

1. 初始读取：成员读取分配资料，输出原生判断、引用及待解决关系；保存逐成员可见资料账本。
2. 任务提出：合并成员疑点和问题分解出的未解决关系。未解决关系允许为空，不强行制造反对意见。禁止读取gold支持句创建疑点。
3. 候选冻结：建立本轮共同核查行动池；所有协调对照拿到同一份候选与元数据。全流水线消融中再单独比较任务提出方式。
4. 价值估计：对成员及行动组合预测纠正、损害、无效及成本；分配前保存特征、分数、模型哈希。
5. 协调：成员对停机、单项或允许的组合行动进行程序化选择。对照均使用相同可行域及相同停止选项。
6. 执行：核查请求绑定同一个轮初状态。选中的配置完整执行，不仅执行第一项；若预算预留不足，不启动配置。
7. 共识更新：先合并证据和支持/冲突/未决关系，再通过固定共同读出生成一个原生答案。原始报告不可改写。冲突不靠模型自报置信度直接胜出。
8. 重规划：更新实际可见状态、预算和任务池，进入下一轮或停止。每轮势函数固定；不声称跨状态全流程具有同一单调势函数。

第一实现版本采用“证据集合合并＋固定读出器”，避免并行答案补丁覆盖。所有方法的读出器完全相同；其调用和Token计入预算。之后若改用确定性读出，必须另立版本，不与当前分数混合。

数据对象：MemberState(member_id, observed_sources, local_reports, history_hash)；CheckTask(target_id, relation, scope, provenance)；Action(member_id, target_id, source_ids, operation)；Review(observations, citations, proposed_decision, validity)；RoundPlan(state_hash, assignments, predicted_value, reserved_budget)；RoundResult(actual_calls, merged_evidence, decision, failures)。这些是接口草案，不是已落地代码。

## 5. 贡献学习与博弈

### 5.1 真实标签

训练侧冻结轮初状态，分别运行空核查、单成员行动、同成员联合阅读、跨成员组合。各分支使用同一读出规则，空核查仍进行读出以控制重新思考。

执行质量用原生答案得分，证据指标作为独立诊断。无效响应保持原状态，其零执行收益计入端到端表现；训练语义结果模型时将无效标为缺失，另训练有效性模型，不把合同错误当作有效零收益。

联合标签来自实际联合执行与合并，不由单成员AB标签代替。采集采用标签不可见的均衡探索，不只采现有模型认为有利的动作；记录采样概率。小规模完整面板只作为局部可达性诊断，不能当可部署oracle成绩。

### 5.2 模型

先比较成员无关Ridge、成员条件Ridge、成员条件概率模型；不默认神经网络更好。输入包括任务及资料特征、局部已读状态、公共未决关系、行动重复和已观察依赖，不包含成员ID、测试标签或支持事实标注。

预测目标为固定状态下完整组合的预期任务增量减成本：F_hat(S,a)=E_hat[Q_after-Q_before|S,a]-lambda*C_hat(S,a)。初始候选和最终读出成本均不得隐藏。成本系数只在训练/校准侧确定；预算曲线另外报告，不凭测试最佳点选主结果。

### 5.3 博弈对象及严格边界

采用边际效用u_i(a)=F_hat(S,a)-F_hat(S,stop_i,a_-i)。固定状态与统一可行域下，严格改善对应势函数上升。共享预算导致可行偏离依赖其他成员，因此单边稳定性应报告为可行偏离下的广义Nash意义，而不是默认独立策略空间的普通Nash。

单边版本和双成员联合提议版本分开。双成员提议须同时满足整体严格改善以及参与者不受损且至少一方改善；若只检查整体改善，应称块坐标协调，不称自愿联盟博弈。两种条件不能在结果出来后互换。由于联合提议可能被成员效用阻挡，需要记录阻挡率，不以虚构转移支付绕过。

固定状态有限配置、严格势函数提升给出终止性；允许双成员偏离的结果只报告所检验邻域内稳定性，不能称全局最优或一般强均衡。所有数学论证须与实际终止容差、可行域和失败回滚一致。

若能建立全域估计误差|F_hat-F|<=delta，预测目标epsilon局部稳定可推出真实目标的单边改进空间不超过epsilon+2delta。这只是拟验证的误差传递命题，不是已成立的统计保证；验证集平均误差不能替代统一误差界。不强套次模性、PoA常数或Stackelberg。

## 6. 基线与公平性

核心对照：单Agent预算内集中阅读；多Agent独立选择；固定轮转；同估计器中央贪心；同估计器中央局部/双块搜索；CBBA适配；边际贡献博弈；小动作空间精确中央枚举。

CBBA先在作者假设适用的标准分配实例上核对实现与冲突消解，再适配本任务。若任务收益违反递减收益等条件，只称适配基线，不继承其收敛或近似保证。

必须包括2×2消融：成员无关/成员条件估计器 × 非博弈/博弈分配。所有组采用同一资料、动作、更新和读出。另比较单边/双成员提议，验证是否真正解决互补性停滞。

中央和博弈访问同一估计器、同一候选和同一预算。完整资料单Agent若超出主预算则另列上界参照，同时提供预算内集中阅读基线，不能删掉强基线。

资源同时记录调用、输入/输出Token、计费估价、协调消息大小、求解时间和端到端时间。相同调用上限不称相同Token；硬预算内不足时停止并记录。并发统一，实验限流等待和模型延迟分开。训练/面板采集费用不隐藏在推理成本之外。

## 7. 实验阶段、规模及启动门

下列数字是待审核的执行规模与工程阈值，不是论文效果或显著性承诺。

| 阶段 | 内容 | 交付与进入下一阶段条件 |
|---|---|---|
| P0 无API | 数据暴露审计、接口、预算会计、求解器与构造实例 | 全部必要正确性测试通过，离线证书一致 |
| P1 开发面板 | 24条预选自然问题，保留全部题；2次重复；同状态跨成员和单成员对照 | 核查/合并可运行，存在可复现的状态或组合依赖；不是仅某一题单次获益 |
| P2 训练与校准 | 拟120训练＋40校准；探索行动与跨成员组合 | 留出校准上能区分行动价值；强非博弈对照不缺失；部署成本可承受 |
| P3 冻结小批 | 60条未用于开发的题，同预算核心对照 | 报告区间和归因，若没有增量不通过追加同类题追求显著 |
| P4 正式检验 | 独立题组，规模依据预设最小效果及开发配对差异计算 | 规则冻结后一次执行；不根据正式成绩扩大样本或更换主指标 |
| P5 迁移 | 原生ReDial、第二模型各自完整同模型对照 | 用于适用边界，不混入主检验制造显著 |

P1每题建议：3次初始读取；1个空分支＋9个单成员动作＋3个同成员双资料动作＋3个跨成员配置，共16个分支。每个核查输出独立调用，跨成员配置2次核查，所有分支1次共同读出，则每次重复上界为3+18+16=37请求；24题×2重复约1776请求，不含重试。双资料在一次请求内读取，Token仍真实计费。动作按预先固定的无标签平衡规则抽样；不足动作不造材料、不换题，记录实际数。两次重复分别生成，不能从缓存拿同一个响应充当独立重复。

该规模仅为上限估算。P0后先导出逐阶段准确请求/Token预算清单，待审批才采集。不得默认把这份方案视为1776次调用授权。P2以后费用须重新估算，不提前给无依据的人民币或耗时承诺。

建议工程门：P1格式与可见引用有效率>=95%，预算越界和标签泄漏为0；语义质量不由这一门认证。科学门报告有益/有害/无效、两次重复一致性、组内交换效应与组合依赖。若信号不稳定，先判断采样噪声与研究假设不足，不设“至少发现几个好题”后挑题入主集。

## 8. 验收与失败分支

主质量指标首域使用原生答案F1，EM辅助，支持事实P/R/F1独立报告；推荐阶段另立原生指标协议。主比较预先指定完整方法对同估计器中央局部搜索，另报告与单Agent强基线的差异。核心多重比较采用Holm校正，题级配对bootstrap；推荐按会话聚类。最低实际意义阈值和非劣界限须在P3前根据任务要求及开发结果冻结，不能在测试后补选。

不能同时把“提准”与“省资源”作为任意择优出口：默认主目标为固定预算质量增量。若要采用质量非劣＋资源节约，须在正式检验前明确选择、冻结非劣界限及资源主指标，并告知用户贡献口径改变。

- 无真实成员差异：不扩充玩家或编造角色；取消异质协调主张，检查局部状态是否实际送入模型。
- 有行动增益但估计失败：在训练侧改估计与探索；新模型用新留出题验证，不反复拟合原24/60题。
- 估计有效但求解器同效：报告理论/执行性质；不能把共有估计器收益署名给博弈。
- 只有双块搜索获益：与同邻域中央块搜索比较；若同效，不称博弈独有算法增益。
- 引用合法但答案仍错误：归为语义或推导问题，不能无限放宽合同到“任何修改都通过”。
- 全资料单Agent同预算更强：保留结果；不得只删掉充足预算或简单样本来制造优势。
- 真正超过强对照：冻结版本、独立确认，再更新中期报告与论文的优势结论。

- ECON，https://arxiv.org/html/2506.08292v1 ：借鉴可学习的成员条件策略与协作价值；不声称本API方案已经复现其训练、假设和BNE保证。
- Utility Design for Distributed Resource Allocation，https://arxiv.org/html/1807.01333 ：借鉴局部效用与整体效率的对应；本文拟议非单调组合收益不直接继承其PoA界。
- CBBA，https://dspace.mit.edu/entities/publication/b0bf0a05-be3b-433b-9f4b-ce314ed5178b ：借鉴局部出价与冲突消解，并作为正式适配对照。
- QMIX，https://proceedings.mlr.press/v80/rashid18a.html ：借鉴集中训练/分散执行的区分；不照搬单调混合假设处理有害证据和互补核查。
- HotpotQA，https://arxiv.org/abs/1809.09600 ：采用多文档及支持事实评价依据，原生任务适配必须单独核验。

边际贡献效用、势博弈终止、成员条件估计和块更新本身都不是新发明。候选贡献是这些组件如何针对证据核查的重复/互补、局部状态及错误更新形成可验证机制。若强对照解释全部增量，应如实缩减创新主张；不能保证审核通过就一定产出正结果。

## 11. 审核点

审核内容为：研究问题与博弈对象是否接受；成员差异是否来自真实局部状态；中央强基线是否保留；默认质量增量主目标是否接受；P0无API实现及后续独立预算审批是否接受。

审核通过后先执行P0，提交代码、必要测试结果和准确采集预算，再启动获准的小批。当前没有新增实验、费用或正向效果，未对正在运行的其他批次做任何干预。
