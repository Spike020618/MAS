# 原过程合同的博弈结构核查：执行结果

范围：旧过程合同及冻结主实验与当前来源获取势博弈的对应。只做研究检查，不修改论文、专利、系统或原始结果；无API调用。

## 1. 核查结论

**不能将来源共享的非平凡精确势博弈证明直接套在旧过程合同上；单纯提高奖励也不能完成两者统一。**现有准确率提升仍为306/450→370/450，但它是公开合同诱导模型使用不同执行路径的经验结果，不是已验证的效用最大化均衡或同伴审议纠错证据。

这不是第二个研究点，而是同一研究中最终方法的归属检查。必须先解决它，再冻结统一算法。

## 2. 实际检查了什么

- 读取contracts.py的支付规则、controller.py的结算/信誉、collect.py的真实执行和信息流、formal_v10.json的冻结参数。
- 对主实验1350条条件级问题记录、20250个Agent轮次逐条复算信用、费用和信誉。无不一致；不假定JSONL顺序就是历史采集顺序，每次从记录的前状态复算。
- 对6750条Static AEIC行动检查声明收益的上下界。3843次为AEIC或Verify，与记录高资源行动率56.93%一致。
- 新增测试检查支付与同伴/答案键的独立性、“consistency”的实际含义、静态合同不受信誉改写，以及可分离收益的平凡势性质。

复核脚本：experiments/mechanism/audit_contract_game_alignment.py。
结果：experiments/results/mechanism/synthesis/contract_game_alignment_2026-10-21.json。

## 3. 发现一：旧静态信用并没有来源共享的行动外部性

旧主实验static_aeic使用fixed_process_quality：

credit_i = 0.2 × complete_aeic(report_i) + 0.2 × nonneutral_C(report_i)

utility_i = credit_i − cost(action_i)

complete_aeic是四字段非空比例；名为consistency的第二个信号仅检查C能否提取为非中立立场，不检查I→C逻辑一致性、同伴一致性或事实正确。代码测试已验证答案错误也能获满额0.4信用。

冻结历史、独立执行和报告生成分布后，Agent自己的期望支付不直接依赖其他Agent当前行动。条件性单阶段收益是可分离的。其和可以构成平凡的精确势函数，但这没有来源竞争、贡献共享或协调分工含义，不宜作为资源协调创新。

有同伴信息的扩展条件可能通过过去报告改变当前信息；这不等于当前联合行动具有来源分享支付结构。更复杂自适应规则另行处理，不能从Static结果推及它们。

## 4. 发现二：声明收益无法解释实际高投入选择为最佳响应

| 行动 | 信用范围 | 成本 | 即时净收益范围 |
|---|---:|---:|---:|
| Low | [0,0.4] | 0 | [0,0.4] |
| AEIC | [0,0.4] | 1 | [-1,-0.6] |
| Verify | [0,0.4] | 2 | [-2,-1.6] |
| Imitate | [0,0.4] | 0.2 | [-0.2,0.2] |

即使高投入必得满分、Low完全没有信用，AEIC和Verify的净收益仍更低。因此，在所声明即时目标下，两种高投入被Low严格支配，且不依赖未知成功率。实际3625次AEIC、218次Verify不能解释为最大化该目标的理性响应。

这里的0.2来自冻结记录与reward_scale，不是仅看未缩放默认参数。不能事后改历史奖励或推测模型理解了另一种单位。该结论不证明模型没有任何内在目标，只证明观测行为不符合我们声明的这一目标。

## 5. 发现三：信誉有记忆，但不是已定义的动态均衡

信誉按0.9×旧信誉＋即时效用更新，实际记录与公式一致。信誉进入后续行动选择提示；Static合同本身却不随信誉改变。当前没有给出折扣累计目标、终止收益或信誉兑现资源规则，因此不能借“未来信誉收益”挽救即时严格支配问题。

控制器还跨问题保持状态，Outcome Only最后一轮依答案键结算，其数值信誉可能影响之后的问题选择。这是顺序反馈设计，不应简单表述为所有测试问题完全无状态、独立采样；不能仅凭存在反馈就认定直接答案文本泄漏。必要时利用已有reset/hidden实验分析其影响，并核查原有统计独立假设。

## 6. 发现四：主实验不是三轮同伴纠错实验

冻结主配置behavior=independent。peer_context在此条件始终返回无同伴信息和空证据，即使记录结构列出了上一轮其他Agent的ID，也不表示其内容真正进入提示。

每轮仍会重生成报告，且后续选择可看到自身信誉；最终按末轮报告多数聚合。不能据此声称“同伴审议三轮纠正了64题”。64是不同机制条件最终结果的净差，不是同一运行的跨轮纠错数。信息环境扩展和历史评审面板另有互动证据，必须按各自协议解释。

## 7. 与来源势博弈的对应判定

| 对象 | 旧静态合同 | 来源获取模型 |
|---|---|---|
| 选择策略 | LLM按提示选择四行动 | 程序比较明确效用、选择D/R |
| 支付依据 | 自身报告字段、非中立C | 执行器确认的来源获取 |
| 他人当前行动影响支付 | 无直接影响 | 同来源人数改变每人份额 |
| 理论性质 | 条件性可分离，平凡势结构 | 非平凡来源共享精确势结构 |
| 高投入理性性 | 声明即时收益下不成立 | 可逐策略计算偏离收益 |
| 质量证据 | 正式主实验有提升 | 新独立小样本未建立提升 |

仅保留同一个AEIC字段，或将两段流程放在一张图中，都不能完成方法统一。

## 8. 核查后的明确决定

1. 旧收益保留，解释为合同提示影响资源选择与模型路由的经验结果；不称已达到Nash均衡。
2. 旧Static不改名为非平凡协调势博弈，不用其准确率作新来源机制性能。
3. 不只把reward_scale调大：这至多解除即时支配，并不会创造Agent间支付外部性或证明LLM执行最佳响应。
4. 不把Verify重复模型自查称为独立客观来源核验。现有外部来源协议与旧自查动作分开。
5. 暂不启动桥接付费实验。先定义最终资源单位：是模型推理预算，还是可共享的来源获取；核查所选单位是否具有真实共享和重复成本。来源包模型不能未经定义迁移到模型调用动作。
6. 下一步只做最小行动—资源—支付映射及简单分配离线比较。若对应不成立，不能承诺只是几行参数修改即可保留旧收益。若成立，再冻结一个最终方法、比较无机制/旧合同/最终方法；沿用旧题只能作开发回归，不能伪称独立测试。

仍然只有一项研究：公开规则如何改善多Agent信息生产与集体决策。现阶段获得的是一次明确的排错结果，不是统一理论已成立。对旧算法定理适用性核查未通过，不得将它写为已修复或已完成最终机制验收。
