# 理论复查：信用分配不等于效果

## 结论

本轮明确两个不能跳过的区别：

1. 合作博弈的定义与梯度正确，不保证有新信息或总体正确率提升。
2. 普通反事实均值baseline保持梯度期望，但不保证比不减baseline的方差更低。

这些是已知理论的适用性复查，不作为我们的原创定理。新增的语言取证行动必须另做真实实验。

## 1. 有限取证博弈

给定公开问题与已固定查询候选，两个程序主体各选择一个取证动作。执行器实际调用同一个检索器并合并材料，固定求解器返回答案。联合动作决定任务得分与真实成本；若主体共享该目标，这是有限共同收益博弈。

共同收益的全局最大动作是纯策略纳什均衡，是基本性质；不代表训练找到了它，更不代表在未知问题分布上最优。神经策略、部分可观测状态及估计critic的收敛不能从这一有限例子自动推出。

本开发屏每个不同的证据输入只观察一份最终响应，因此得到的是冻结响应实现上的经验表。它不等于已知的模型期望收益表。完全相同输入复用响应，避免随机差异冒充动作差异；不同输入间的采样噪声仍存在。

## 2. baseline的梯度条件

设单个主体的softmax策略为π，动作a，梯度分量记g(a)=∇logπ(a)。若b在给定状态和其他主体动作后不依赖当前动作，则：

`E[g(a)(R(a)−b)] = E[g(a)R(a)]`。

依据是`Σ_a π(a)g(a)=0`。这不要求b等于平均奖励，也不要求它是准确的价值函数。

但如果critic用当前动作/回报拟合后，以隐含方式将当前动作信息写进baseline，无条件无偏性就不能仅凭“输入字段没有action_i”断言成立。应冻结或交叉拟合估计器，并区分真实回报减baseline和直接以估计Q替换真实回报两种更新。

## 3. 方差反例

两动作的概率为(0.1,0.9)，奖励为(0,1)。计算softmax-logit梯度的总方差：

| baseline | 梯度期望 | 梯度总方差 |
|---|---|---:|
| 0 | (−0.09,0.09) | 0.0018 |
| 普通反事实均值0.9 | (−0.09,0.09) | 0.1152 |
| score加权最优baseline0.1 | (−0.09,0.09) | 约0 |

普通均值在这个例子反而使方差扩大64倍。因此不能把“反事实信用一定更稳定、样本一定更省”写成理论结论。

对固定条件下的score向量，最小化梯度二阶矩的动作独立常数为：

`b* = E[R ||g||²] / E[||g||²]`。

该式来自平方项最小化，已有经典研究，不能视为新算法发明。实际Q不准、样本不足或使用其他参数化时，还需要另行估计与误差控制，不能把精确小表结论直接外推。

来源：[Greensmith等，JMLR 2004](https://www.jmlr.org/papers/v5/greensmith04a.html)；反事实多Agent背景：[COMA](https://arxiv.org/abs/1705.08926)。

## 4. 对新设计的修正

- 标准COMA-style信用是基线而非默认胜者；后续学习应比较无baseline、共享奖励、反事实均值与score加权基线。
- 参数更新、低方差、经验偏离低、最终正确率高，是四个不同指标，必须分开。
- 反事实评估自身消耗调用，不能把更多评估样本换来的效果当等成本收益。
- 查询集合的Shapley归因、COMA的条件反事实baseline和真实支付不是同一对象，不混用定理。
