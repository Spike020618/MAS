# 最终人工盲审操作说明

## 一、目的与边界

人工审核只补充程序无法替代的主观判断，不修改自动实验结果，也不用于重新选择模型、参数或样本。审核者在填写前不查看方法名称、自动得分或最终统计。

## 二、AEIC报告质量盲审

发给审核员的文件：

- `experiments/results/human_review/aeic_review_A_blind.csv`
- `experiments/results/human_review/aeic_review_B_blind.csv`

原始工作簿`docs/research/AEIC_report_interface_human_review.xlsx`保留为生成来源和旧版汇总模板，不直接发给审核员。盲审CSV删除了标准答案，并为两名审核者使用不同的固定随机顺序。

审核人数：2人。两名审核者独立完成，不讨论后再打分。

逐条判断：

1. 假设是否明确说明回答成立所依赖的前提；
2. 证据是否与当前问题和结论直接相关；
3. 推断是否能够由给出的假设与证据支持；
4. 结论是否明确回答任务；
5. 报告是否存在无依据事实、循环论证或字段重复；
6. 给出整体质量等级及一句简短理由。

如无法判断，使用表内“不确定”选项，不根据语言流畅度猜测事实正确性。

完成后统计两名审核者一致率；分歧项保留原始评分，并由第三人只对分歧项复核。不得删除低质量样本。

## 三、影视推荐结果盲审

发给审核员的文件：`experiments/results/human_review/movie_review_blind.csv`。

`movie_review_key.csv`是回填映射，只能在审核结束后使用，不发给审核员。盲审文件删除系统综合分并采用固定随机顺序。

审核人数：1人；条件允许时可增加第二名审核者，但不作为当前验收前提。

逐条判断：

1. `relevance`：影片是否符合请求的核心偏好；
2. `reason_factuality`：推荐理由是否只使用目录和请求中可支持的信息；
3. `list_fit`：该影片放入当前Top-5后是否造成明显重复或破坏列表整体适配；
4. `hard_constraint_issue`：是否发现年份、类型或排除条件错误；
5. `comment`：仅记录具体问题，不写泛化评价。

推荐评分采用统一三级标度：`2=满足`、`1=部分满足或不确定`、`0=不满足`。硬约束问题使用`0/1`记录。

审核者不得根据综合分、Agent数量或系统方法推测“正确答案”。片名陌生或证据不足时应标记不确定。

## 四、结果汇总原则

- 自动指标与人工指标分开报告；
- 不把人工相关性解释为ReDial离线命中率；
- 不把理由通顺解释为事实正确；
- 不因审核结果不理想而移除样本；
- 报告有效样本数、缺失数和不确定数；
- AEIC双人审核同时报告一致率。

## 五、完成定义

开始前在`review_assignments.csv`填写匿名审核员编号；完成后填写审核日期并将`completed_0_1`改为1。

完成以下三项即视为人工阶段结束：

- 两名审核者分别提交完整AEIC盲审表；
- 150条影视推荐记录完成审核；
- 汇总脚本或人工复核确认无空白必填字段，并保存审核日期与审核者匿名编号。

完成后运行：

```bash
/Users/spike/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 experiments/summarize_human_review.py
```

脚本只在所有必填评分合法时生成`human_review_summary.json`；任一空白、越界值或两名审核者样本集合不一致都会停止汇总。
