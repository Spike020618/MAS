# 可核验语义交互：文献调研与研究取舍

## 结论

不再把“多想一次＋多数决策”作为核心新方案。建议只保留一个待验证研究问题：**在给定预算与真实证据权限下，策略性局部核验能否比直接求解、普通审阅及非博弈调度更可靠地纠正集体错误？**

这是本轮调研后的研究建议，不是已经有效的新机制。正式题目不在本轮修改。没有新增付费模型调用，没有改论文、专利、系统或历史冻结证据。

调研覆盖原论文方法、部分实验与假设章节，以及 PEG、Neural Interactive Proofs 作者代码入口。没有执行作者 Notebook，也没有复算这些论文的实验结果；以下数值均为作者报告，不是我们的复现。

## 一、真正相关的参考与不可照搬之处

### 1. 辩论的收益取决于可用信息，而不只是轮次

ICML 2024《Debating with More Persuasive LLMs Leads to More Truthful Answers》在专家能访问材料、裁判缺少材料的设置下报告正向结果。重要参照是信息不对称条件，不应把作者成绩移到我们的闭卷同模型设置。

[论文](https://proceedings.mlr.press/v235/khan24a.html)

NeurIPS 2024《On scalable oversight with weak LLMs judging strong LLMs》进一步比较信息、计算及多模态不对称：相对直接问答的收益依任务而异。文中引用校验仅检查摘录是否存在于原文，不能证明引用支持结论。

[方法、实验及附录G](https://arxiv.org/html/2407.04622v1)

**对我们的约束：** 不能再把同一模型多生成一段解释称为独立证据。若引入受限材料权限，必须同时报告裁判直接读取全部材料的强基线；不能通过人为削弱基线制造协议优势。

### 2. AgentAuditor：查推导分叉，而非整段解释打分

2026 预印本《Auditing Multi-Agent LLM Reasoning Trees Outperforms Majority Vote and LLM-as-Judge》把推导拆成树，在关键分叉处比较局部证据，报告相对多数与普通裁判的收益。其偏好优化变体涉及 LoRA 训练，不能当成纯 API Prompt 即可获得的效果；外部求解器/检索增强在文中仍列为未来工作。

[方法与实现附录](https://arxiv.org/html/2602.09341v1)

**值得借鉴：** 把“具体哪一步可能错”变成核验对象。**不能照搬：** 将重复报告聚成树不自动得到事实真伪；我们的旧前提核查已失败，单纯再写一个局部审计提示词并非新方案。

### 3. Minority Sentinel：学何时改判，而非一律相信少数派

2026《Minority Sentinel》使用辩论行为特征和部分额外语义审计训练分类器，报告净增益 +1.71 个百分点，而非恢复全部约10个百分点的离线空间。论文在分域 OOF 预测上选阈值，仍需独立或嵌套校准核查；它还依赖额外 GPT-4o 审计。范围限于特定三 Agent 分歧设置，不能解决所有一致错。

[方法、校准及局限](https://arxiv.org/html/2606.29270v1)

**值得借鉴：** 衡量正确改判与错误改判的净差，限制误翻转。**不建议直接做：** 用我们当前仅一个可恢复错误训练高维选择器，或在测试集搜索阈值。

### 4. PEG：最直接的同行信息博弈参考，但诚实不等于正确

NeurIPS 2025《Incentivizing Truthful Language Models via Peer Elicitation Games》用多判别者的行列式信息分数与策略更新，提供公开初始策略数据及 Notebook。其“truthful”首先是报告与私有信号一致；理论涉及任务分布、信号条件独立、局部策略等假设，不能据此保证同源模型的错误判断变为客观真相。

[论文与假设](https://arxiv.org/html/2505.13636v2) · [作者代码与已有策略数据入口](https://github.com/toz015/neurips2025-repo)

**研究价值：** 优先核查原始代码的收益和更新是否一一对应，区分信息报告与答案正确性。独立进程或不同采样不意味着给定真值后的错误条件独立。绝不直接挪用“唯一真实均衡”作为我们方法的定理。

### 5. Neural Interactive Proofs：博弈应落在验证协议本身

ICLR 2025《Neural Interactive Proofs》统一验证者与不可信证明者交互，讨论验证者领先的双层优化，并在代码验证上训练与测试协议。其语言模型实验涉及多轮微调，不能把固定 API 提示词交互称为该训练方法的复现，也不能由此承诺全局最优或严格均衡。

[论文](https://arxiv.org/html/2412.08897v2) · [作者代码](https://github.com/SamAdamDay/neural-interactive-proofs)

**对我们的启发：** 有理论支撑的交互对象是“证明是否经得起挑战”，不是给共识程度付费。我们可以先做有限协议菜单的程序化博弈，但其数学解必须与实际协议、实际风险表对应。

## 二、为什么不是把我们之前失败的方案重做一遍

| 已失败或未成立的做法 | 必须改变的实质条件 |
|---|---|
| 同模型重复生成解释 | 新行动必须获得未在初始上下文中的材料、可执行检查结果或真正互补的信息 |
| 全局角色可靠性加权 | 使用题目级、可复验的核查结果；先验证它的判别能力 |
| 前提核查与普通审阅均不增益 | 新方案不能仅更换 Prompt；要有可追踪的取证动作与证据权限 |
| 压力/中性表达的静态风险矩阵 | 若研究策略对抗，挑战必须涉及实质论证，且允许对固定协议作适应性反应；不能只换措辞 |
| 加一个均衡求解器 | 非博弈控制器必须拥有同样反馈、同样动作空间、同样预算 |
| 过程字段完整即奖励 | 引用存在、论证支持、最终正确分别评分，不将格式与语义效果混为一谈 |

对照本地证据：《关键前提核查_失败来源诊断_2026-10-24》《核验交叉开发_结果与取舍_2026-10-24》《可学习协调_三步执行结果_2026-10-25》。这些结果保留，不在原题上调参翻案。

## 三、建议的最小方法，而非继续扩展大系统

### 语义交互

先独立判断并封存；对冲突、关键未支持前提或随机审计抽中的一致态，定位一个会改变结论的主张。提议者提交来源片段与推导，挑战者指出反例或缺失上下文，核验动作访问真实原文/检查器，最终决策允许保留原结论或弃答，不默认必须翻转。

必须保留三层区分：来源是真的，不代表来源支持主张；主张得到支持，不代表推导全部成立；推导合规，不代表测试答案一定正确。不能因为全部 Agent 初始一致就拒绝审计。

AEIC 如继续保留，只承担假设、引用、推导和更新的日志接口，不预设四字段不可替代；关键是实际查询/核验是否产生结果，而非模板名称。

### 真实行动

第一种：根据查询读取原始材料的局部片段、相邻上下文或另一来源；证据链须含文档哈希、位置和检索请求。原始材料来自独立公开来源或任务原文，不是官方答案解释、人工金标准分解或缓存的模型正确答案。

第二种：调用允许的客观检查器验证一个明确断言。有限测试只支持“通过这些测试”，不能宣称程序完全正确。若涉及不可信代码，必须先有隔离执行环境、时间/资源上限和无网络权限，不能直接在主机执行模型代码。

不要求同时实施两种工具；先选一个最小环境验证，另一种只能作为后续迁移，而不是新增第二研究方向。

### 博弈的位置

定义为“有限预算下的证明—挑战—核验协议选择”。程序证明者偏好其主张被接受；验证者优化误收/误拒风险与核验成本。策略真实控制提交什么论证、挑战哪一步及查询哪个片段，而非给 LLM 发一句奖励提示。

具体零和/一般和、谁先承诺及均衡概念，应由实现的行动与收益决定。先核对收益矩阵、反馈和实际调用，不能为了保留 Stackelberg 或势博弈而先写证明。有限经验矩阵解只对应已观察菜单，不证明自然语言全策略最优。

## 四、执行顺序与停止条件

### P0：先做作者方法与接口对照，零新增付费调用

审查 PEG 作者 Notebook 和已有策略数据、AgentAuditor 的局部审计输入、NIP 的协议与损失。只读分析，不直接执行第三方 Notebook。建立“理论变量—代码字段—API/工具行为”映射。发现答案键进入行动、缺失概率补值或相互独立假设无依据时，单独报告，不绕过。

PEG 历史公开数据包含作者使用的其他模型输出，读取论文/数据不等于调用这些模型；实际新采集仍只使用已授权 DeepSeek，不调用 Qwen。

### P1：先验证核验行动，不加支付

使用一个小规模、输入预定的原生题组，所有题保留，不只挑多数错或已知可纠正题。四个必要参照：同模型直接读全部材料、同预算独立求解/固定取证、普通审阅、局部证据核验。总成本包含提案、检索、核查和失败调用。

这一步只问：新动作是否比普通审阅更能区分正确与错误，是否产生净纠正？没有信号则停止，不进入博弈，不继续增加字段。小样本仅作开发闸门，不凭两三题宣布有效。

### P2：有真实信号后，才检验协调的必要性

训练/校准中比较固定动作、同预算随机、普通贪心/集中式优化与博弈策略；所有方法获得相同可见状态、反馈和资源菜单。还要比较“只选一个训练表现好的核验器”。若一个固定强协议全面占优，直接采用它，不刻意制造协议互补。

### P3：锁定后独立测试

按文档/原始题组隔离，而非把同一问题的不同候选分到两边；校准阈值仅用训练/验证。必须同时报告总体准确率、正确与错误改判、误收/误拒、弃答/覆盖、调用/Token/延迟和最强简单参照。策略性核查另报告预定威胁模型下的经验偏离收益，不将其替换为准确率。

没有超越非博弈控制，不写博弈独立贡献；只有鲁棒性/核验成本收益，就按该指标收窄，不宣传普遍提准。若没有新动作增量，也没有协调增量，应停止该分支而非再次扩大测试。

## 五、可直接使用的公开材料

- 文档型可核验输入：[QuALITY 官方仓库](https://github.com/nyu-mll/quality)。模型可见题目与原文，答案标签隔离；需先核对许可与数据划分。全文读取必须是强基线，不能只与无文档问答比。
- 验证型迁移参照：[NIP 作者 buggy-apps 数据](https://huggingface.co/datasets/lrhammond/buggy-apps)。必须剥离 checks、flags、correct/buggy 所属字段和文件命名泄漏；实际原生测试与生成的小测试分离，金标准测试不能作为免费答案查询。
- 原方法代码：[PEG](https://github.com/toz015/neurips2025-repo)、[Neural Interactive Proofs](https://github.com/SamAdamDay/neural-interactive-proofs)。先复核，不立即复制强结论。

数据集是检验可核验交互的载体，不意味着把研究改成某一领域解题优化。迁移必须冻结通用接口与规则，不能为某类题逐题加知识。
