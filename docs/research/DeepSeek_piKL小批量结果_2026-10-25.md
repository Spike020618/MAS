# DeepSeek piKL 小批量结果

## 执行口径

用户明确允许直接使用 DeepSeek。使用同一个实际后端 deepseek-flash、指纹 e72d3c7f663d3e1383b00b3884cb4501；非思考模式、temperature=1。固定 eta=lambda=0.1、5000 次同步 piKL 更新，不根据本批答案调参。

六道此前预留、未执行题，StrategyQA/MMLU/TruthfulQA 各两道。选择时排除两批已执行题，并对历史 responses.jsonl 做来源 ID、渲染题干及转义题干匹配，未发现命中。此为精确文本/来源隔离，不保证语义或预训练未见；规模很小，只作开发验证。

每题正/负生成及候选核验共享同一评分池，合计 34 次物理调用。不同读出不重新查询模型。完整封存后读取离线答案；答案不作为 Agent 的证据或评分输入。

## 结果

| 方法 | 正确数 | 弃答 |
|---|---:|---:|
| G 生成排序 | 5/6 | 0 |
| MI 分数组合 | 5/6 | 0 |
| SC 自对比 | 5/6 | 0 |
| D 判别排序 | 5/6 | 0 |
| ER-G 博弈生成读出 | 5/6 | 0 |
| ER-D 博弈判别读出 | 5/6 | 0 |

不仅总数相同，六道题的六种答案逐题全部相同；ER-G/ER-D 相对各简单参照均 0 纠正、0 伤害，配对检验及 Holm 校正均为 1。这里不能据此证明等效，也不能声称博弈在一般条件下无效；只能说本次固定配置未展示增量。

34 次响应全部成功、概率输入全部可用，4,258 Token，计费使用未知项为 0；HTTP 耗时之和 22.7379 秒，不等同于整批端到端耗时。当前六种读出共享评分池，对照不是各自最省调用的独立部署，也未比较同预算完整推理多数投票，不宣称效率优势。

## 与原论文的关系

本次为 DeepSeek 单 Token 编码概率空间适配，不是原论文完整候选文本似然实验。核心同步更新与参考公式对应，但评分输入、Prompt 和模型均与原实验不同。不能将其称为原论文严格复现成功或失败。

旧 12 题回放属于已开卷诊断，与新六题分开保留，不合并成所谓 18 题独立验证。旧 450 题的联合配置收益也不转移给当前新方法。

## 收口

本轮已完成软件实现、DeepSeek 在线小批量和离线可恢复验证，不继续在这六题上更换奖励、正则或筛题寻找正结果。当前结果不支持扩大这个固定评分后处理方案。

后续可学习协调仍是另外需要实现并验证的假设，不能因读出没有增量就假定它必然成功。本轮不把“博弈一定有提升”写入任何论文结论，也不宣布整个研究目标已经完成。
